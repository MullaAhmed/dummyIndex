## Data integrity

- **High** — `dummyindex/cli/refresh.py:37` → `dummyindex/cli/migrate.py:90-92` → `dummyindex/context/output/claude_md.py:221-250` — `refresh-indexes` calls `migrate_claude_md_location` without the `has_foldable_legacy_claude_md` guard (`dummyindex/cli/migrate.py:14-32`). `rebuild` (`dummyindex/cli/rebuild.py:31`), `bootstrap` (`dummyindex/cli/bootstrap.py:80`), and the installer (`dummyindex/installer/install/project_init.py:107,165`) all apply that guard. Two results: on a Codex-only tree the command creates `.claude/CLAUDE.md` from nothing, and when root `CLAUDE.md` is an active Codex `project_doc_fallback_filenames` instruction it deletes that file (`claude_md.py:248`) after moving its content somewhere Codex never reads. Tests cover only the case where a root file is present (`tests/cli/test_migrate.py:62-92`, `tests/cli/test_cli.py:290-330,413-439`). Fix: gate the call in `migrate_legacy_layout` on the same predicate, and add a `refresh-indexes` copy of `test_rebuild_leaves_codex_fallback_doc_alone`.
- **High** — `dummyindex/cli/init.py:70-78` + `dummyindex/cli/wire.py:109-116,239-244` + `dummyindex/context/default_plugins.py:307-325,529-548,701-707` — A custom `config.wired` plugin goes through the reviewed-default declaration path, which writes `enabledPlugins[target]=true` with no `extraKnownMarketplaces` source (only `_default_for_target` hits reach `_declare_marketplace`). Materialisation selects only `DEFAULT_PLUGINS`, so nothing installs. From then on `_already_decided`'s key-presence test classifies the entry `SATISFIED`, so neither `init` nor `wire` ever revisits a plugin that Claude Code cannot resolve unless its marketplace was already declared. Fix: report a custom target with an undeclared marketplace as needs-user instead of enabling it, or persist declaration and materialisation as separate states.
- **Medium** — `dummyindex/cli/wire.py:156-162,240-244` + `dummyindex/context/default_plugins.py:713-742` — `_wire_plugin` treats `not install.errors` as success, so `deferred` (CLI absent) and empty `skipped` both print `wired:`. When the install does fail after declaration already wrote `true`, the "left needs-user" message is false: the next `wire` run classifies the entry `SATISFIED` (`wire.py:109-122`) and never retries. Only `init`'s pass re-attempts, because it checks for effective `true` plus a ready marketplace. Separately, `wire` reads the ledger once (`wire.py:96-115`) and does not re-read it after a blocking prompt, so a stale approved entry can still be enabled. Fix: require `installed` for success, roll back the enable on install error (or persist a pending marker), and re-read the entry from config before mutating.
- **Medium** — `dummyindex/context/build/meta.py:107-115` + `dummyindex/context/domains/config.py:736-756` + `dummyindex/context/claude_settings.py:175-179` vs `dummyindex/context/domains/atomic_io.py:38-68` — The three state files this feature's handlers mutate are `meta.json` (`reconcile-stamp`), `config.json` (`init`), and `.claude/settings.json` (`init`/`wire`). All three write through a fixed `<name>.tmp` sibling with no lock, no cleanup of the tmp file, and no Windows retry. That skips the project's own writer, which uses a unique `NamedTemporaryFile` and retries `PermissionError` because "hooks from two Claude profiles can update the same repo-local cache concurrently". Effects:
  - On Windows, a concurrent reader turns `reconcile-stamp`'s unguarded `write_meta` (`dummyindex/context/build/reconcile.py:361`) into a traceback and leaves `meta.json.tmp` behind.
  - Two writers share one tmp path. The second `replace` raises `FileNotFoundError`, which `init` reports as "invalid config" (`init.py:63-67`).
  - The stamp's read-modify-write of meta is unlocked against `rebuild --changed`'s (`dummyindex/context/build/enriched_refresh.py:345-358,391-408`). Refresh can write back the pre-stamp `indexed_commit` after `cache/manifest.json` and `doc-basis.json` have already advanced (`reconcile.py:362-381`).

  Fix: route all three writes through `write_text_atomic`, and wrap the stamp and refresh meta read-modify-writes in `project_lock` (`dummyindex/context/domains/evolve_promotion.py:21-53`, already used by gc/closeout; its name allowlist at `:24` needs an index lock).
- **Medium** — `dummyindex/cli/init.py:151-165` + `dummyindex/cli/reconcile.py:59-71` + `dummyindex/context/domains/config.py:542-551` — Without `--depth`, `resolve_depth` runs the full strict config parse. A malformed plugin-only field (`wired`, `default_plugins_enabled`) therefore exits 2 before `init`'s build, even under `--no-default-plugins` or `--platform codex`. It also blocks the read-only `reconcile` report, which needs only `mode`/`command_depths`; the plan raises this as an open question for `init` only. Fix: add a depth-only reader modelled on `read_doc_guard_settings` (`config.py:571-596`) that checks only `mode`/`command_depths`, and leave full validation to `_wire_default_plugins_step`.
- **Medium** — `dummyindex/cli/init.py:56-62,73-84,242` — Up to three separate config writes (migrate, equipment fold, default reconcile that sets `default_plugins_enabled=true` and appends defaults) are committed before any settings declaration or `claude` call. `_wire_default_plugins_step` returns `None` and `run` exits 0 regardless. A run whose declaration or materialisation failed therefore leaves durable config intent with no machine-visible partial-state signal (plan open question "Exit code for partial outcomes"). Fix: return the wire/install results to `run`, and surface a documented non-zero exit or a persisted pending marker.
- **Low** — `dummyindex/cli/check.py:238-246,297-305` + `dummyindex/context/build/reconcile.py:357-360` + `dummyindex/cli/reconcile.py:160-173,208-227` + `dummyindex/context/build/meta.py:75-92` — Two handlers lose the type of `read_meta`'s refusal:
  - `check --versions` catches `Exception` and records a newer-schema `meta.json` as `unknown`. That value is left out of `known`, so the skew detector prints "versions coherent" for exactly the newer-writer skew it exists to catch.
  - `reconcile-stamp` reclassifies the error by re-reading the file and substring-matching its prose, and that second read can see a different file.
  - Mistyped fields (`int(None)`, `tuple(None)` at `meta.py:89-92`) raise `TypeError`, which escapes `stamp_reconciled`'s `(ValueError, JSONDecodeError, OSError)` catch. The user gets a traceback instead of the documented exit 1.

  Fix: raise a typed `MetaSchemaError` from `read_meta`, convert field-coercion errors to `ValueError`, carry the error on `StampResult`, and show it as a skew row in `--versions`.
- **Low** — `dummyindex/cli/plan_update.py:54-65,88-91` + `dummyindex/cli/statusline.py:53-63` + `dummyindex/context/hooks.py:147-159` — The per-prompt freshness badge is a derived cache written only by SessionStart's `plan-update`. `reconcile-stamp` changes its inputs (anchor and `doc-basis.json`, `dummyindex/context/build/reconcile.py:361-362`) without invalidating it, and `statusline` echoes the cache verbatim. After a successful stamp, the statusline keeps showing stale drift counts for the rest of the session. Fix: delete or recompute the badge at the stamp write boundary, or have `statusline` print nothing when the badge is older than `meta.json`.

## Security

1. **High — `features-merge --from` deletes any directory it is pointed at.** `dummyindex/cli/features.py:120-161` → `dummyindex/context/domains/features/ops.py:225-241,280`. **Threat:** the CLI passes `--from` through unchecked. `merge_feature` only `.strip()`s it, checks `src.is_dir()`, and then calls `_rmtree(src)`. Run `features-merge --from ../.. --into <any-real-id>` (or an absolute `--from /home/u`) and the domain resolves `features/../..` to the repo root. It appends that directory's `README.md` to `supporting.md` and then deletes the whole tree, `.git` included. The 18-filter-trivial architect copies feature ids straight from `features/INDEX.json` into `--from` (`dummyindex/skills/council/18-filter-trivial.md:74-79`). So a crafted id in a committed curated `.context/`, or injected doc text, reaches `rmtree`. Two siblings take the same unchecked id. `features-rename --from` moves an arbitrary directory into `.context/` (`ops.py:84-103`). `flow-remove --feature/--flow` unlinks any `<x>.json`/`<x>.md` (`ops.py:366-376`). **Mitigation: none on these paths.** The slug guard `_validate_feature_id` exists (`dummyindex/context/domains/features/helpers.py:22-33`). `features-remove` applies it, with a comment naming this exact `../sibling` → `_rmtree` attack (`dummyindex/context/domains/features/placement.py:294-297`). Rename and merge apply it only to the *destination* id (`ops.py:85,227`). The plan's "value flags are allowlisted per command" decision (`plan.md:145-147`) checks flag names, never values. **Fix:** slug-validate every source id at the CLI boundary or in the domain.

2. **High — settings writes follow symlinks the repo ships, which lets a clone install hooks into the user's global Claude settings.** `dummyindex/context/claude_settings.py:175-179` (predictable `settings.json.tmp`, written through `Path.write_text`). Reached from `dummyindex/cli/init.py:221-231` → `dummyindex/context/hooks.py:519-542` → `claude_settings.py:64-113`, and from the plugin step (`cli/init.py:70-78`, `cli/wire.py:239-244` → `dummyindex/context/claude_plugins.py:105-155`). **Scenario on a POSIX clone:** the repo commits `.claude/settings.json` carrying its own hook commands. It also commits `.claude/settings.json.tmp` as a symlink to `../../.claude/settings.json`. The user clones to `~/<repo>` and runs plain `dummyindex ingest`. Hooks install by default; it loads the repo settings, appends dummyindex's hooks, and `write_text` follows the `.tmp` link. The result: `~/.claude/settings.json` is replaced by the repo's hooks. Those hooks then run in every Claude session in every project, outside per-folder workspace trust, and the user's own global settings are destroyed. A `.claude` directory symlink does the same for `enabledPlugins`/`extraKnownMarketplaces`, and `_already_decided`/`_effective_enabled` then read through that same link (`dummyindex/context/default_plugins.py:307-340`). **Mitigation: none in init/wire/hooks.** Equip already refuses linked settings paths (`dummyindex/cli/equip/dispatch.py:613-624`, `_has_symlink_parent` `:714-720`), though it doesn't check `.tmp` either. The repo also has a collision-safe unique-tempfile writer (`dummyindex/context/domains/atomic_io.py:38-68`) that `write_settings` doesn't use. Git for Windows' default `core.symlinks=false` blunts this only for Windows clones.

3. **High — on Windows, a `claude.exe` (or `git.exe`) committed at the repo root runs when `ingest` is executed in the clone.** `dummyindex/context/default_plugins.py:626-628` runs the bare name `["claude","--version"]` through `default_runner` (`:589-605`). Windows `CreateProcess` searches the *parent's* current directory before `PATH`, and the `cwd=` argument does not change that search. **Scenario:** a fresh clone has no `.context/`, so the reviewed defaults are declared and eligible (`cli/init.py:70-78`, `default_plugins.py:711-742`). The probe then executes the repo's binary before any Claude workspace-trust prompt. **Verified in this session:** a copy of `whoami.exe` saved as `claude.exe` in the working directory ran instead of `~/.local/bin/claude` under default env. It was blocked only when `NoDefaultCurrentDirectoryInExePath` was set; this harness sets it, a normal terminal does not. The bare name `git` has the same exposure (`dummyindex/context/git.py:65-74`, `dummyindex/context/build/git_delta.py:299`), reached from `reconcile-stamp` and `status` (`cli/reconcile.py:123`, `cli/status.py:217`). On POSIX the prior inherited-`PATH` scenario still holds. **Load-bearing mitigation:** `--no-default-plugins` / `DUMMYINDEX_SKIP_PLUGIN_INSTALL` (`default_plugins.py:735-738`) skip the `claude` probe only. List argv, no shell, and the 60 s timeout limit the arguments, not which binary runs. **Fix:** resolve an absolute executable from `PATH` entries, excluding cwd and the repo root.

4. **High — `section-write` overwrites any existing `.md`, and its guard treats "the file already exists" as permission.** `dummyindex/cli/features.py:215-245,285-298` → `dummyindex/context/domains/features/ops.py:453-470`. **Threat:** `--feature` is never slug-checked. `write_section` rejects only `/` and a leading `.` in `--section`. `--feature ../../.claude --section CLAUDE` (or absolute `--feature ~/.claude`) passes the guard because `(features_dir / feature_id / "CLAUDE.md").is_file()` is true, then rewrites the repo's or the user's global `CLAUDE.md` with `--from-file` content. That is persistent instruction injection into every later session. On Windows, `--section` also accepts `x\..\..\..\..\CLAUDE` and drive-absolute `C:\…`. Every council stage calls this verb, with arguments built from repo-derived text. The writes happen as a Bash command, so they bypass the `PreToolUse` doc guard (matcher `Write` only, `dummyindex/context/hooks.py:245-249`) and Claude Code's Write-permission prompts. **Mitigation: none.** The guard exists to stop a stray `security.md`; it does not contain paths.

5. **Medium (regressed) — the reviewed third-party defaults that run code are now unpinned and on by default.** `dummyindex/context/default_plugins.py:120-145,165-193`: there is no pin field and the defaults "track latest". `caveman` ships Node SessionStart and UserPromptSubmit hooks; `i-have-adhd` ships a shell hook. On top of that, `_declare_marketplace` *rewrites* an existing ≤0.33 full-SHA pin to unpinned (`:353-409`). Then `claude plugin marketplace add <repo>` and `claude plugin install` fetch the current default branch (`:646-667`), reached from default `init` (`cli/init.py:236-240`). **Scenario:** a push to, or takeover of, `JuliusBrussee/caveman` or `ayghri/i-have-adhd`. On the next install or session, every dummyindex repo runs that code on every prompt. The committed `enabledPlugins` and `extraKnownMarketplaces` spread it to every teammate. **Load-bearing mitigation:** only opting out — `--no-default-plugins` or `default_plugins_enabled=false`. The disclosure (`:196-214`, printed at `cli/init.py:46-49`) says "reviewed surfaces" about code nobody reviewed, so the plan's "disclosure precedes plugin mutation" decision (`plan.md:162-163`) is a gesture. **Fix:** make `runs_code=True` defaults opt-in through `wire`, or pin to a reviewed tag and verify the commit after the clone.

6. **Medium — headless `init` turns any custom `config.wired` plugin into `enabledPlugins=true` with no approval, then hides it from `wire`.** `dummyindex/cli/init.py:70-73` → `dummyindex/context/default_plugins.py:529-548`: a custom target skips the marketplace step and gets `enable_plugin`. **Scenario:** a PR adds `{"kind":"plugin","target":"<hook-running-plugin>@claude-plugins-official"}` to the generated, rarely reviewed `.context/config.json`. Each teammate's `ingest` then writes it into the reviewed `.claude/settings.json`. Classification checks only that the key exists (`:307-325,448-469`), so the next `wire` calls it `SATISFIED` and never shows the "untrusted plugin" prompt (`cli/wire.py:109-123,209-218`). The plan's "approval is target-scoped" (`plan.md:170-172`) holds only inside `wire`. **Load-bearing mitigation:** the materialiser keeps only `DEFAULT_PLUGINS` (`:701-707`), and an undeclared custom marketplace does not resolve. So only plugins in already-known marketplaces can be activated. The repo could also commit the key directly; the added risk is laundering the change through a less-reviewed file and switching off the approval surface. Rated down from High for that reason.

7. **Medium — escape sequences in config targets let a repo hide or forge `init`/`wire` output.** `WiredEntry.from_dict` accepts any non-empty string (`dummyindex/context/default_plugins.py:102-104`). A `kind=skill` target never has to resolve, so it can carry arbitrary ESC/CSI sequences (as JSON `\u001b`). `init` prints warning lines to stderr after the info lines (`cli/init.py:79-84` via `default_plugins.py:294-303`), and `wire` prints targets raw (`cli/wire.py:133-134,141-166`). **Scenario:** a skill entry `x\u001b[3A\u001b[J…` erases the earlier `plugins -> enabled <custom>@…` line from #6 and prints a harmless-looking substitute. In `wire --yes`, a later skill entry can overwrite the `wired:` lines and the summary. **Mitigation: none.** There is no control-character filter anywhere under `dummyindex/`. `reconfigure(errors="backslashreplace")` (`dummyindex/__main__.py:282-286`) only affects characters the console can't encode, and ESC can be encoded.

## Product surface
