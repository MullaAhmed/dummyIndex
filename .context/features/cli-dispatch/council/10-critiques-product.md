## Product surface

- **High — orphaned anchor plus real blockers: `reconcile-stamp` names the wrong remedy and `reconcile` hides the blockers.** Scenario: history was rewritten (anchor missing from repo) and a feature still carries `.pending-enrichment` or files are unassigned. Observed: `reconcile-stamp --heal-orphaned` prints `warning: --heal-orphaned: … re-baselining at HEAD <sha>` to stdout (`dummyindex/cli/reconcile.py:114-134`), the re-stamp with `to_commit=head` is refused on blockers (`dummyindex/context/build/reconcile.py:342-348`), and `_render_stamp_refusal` still sees `anchor_broken` (the report is recomputed from the unchanged meta) so it prints only the orphan text — "Re-baseline with `reconcile-stamp --to <commit>` … or pass --force" — and returns 1 without listing a single blocker (`dummyindex/cli/reconcile.py:148-149`, `:256-267`). An explicit `--to <sha>` gets the same refusal, which again tells the caller to pass `--to`. The read-only `reconcile` text report also returns right after the orphan WARNING (`dummyindex/cli/reconcile.py:324-333`), although the report has computed `unassigned_new_files`/`awaiting_enrichment` (`dummyindex/context/build/reconcile.py:170-181`) and help promises both lists (`dummyindex/cli/help.py:185-191`). Gap: stdout says the anchor is being re-baselined while stderr says it was refused. The only remedy the output names is the one just tried, so `--force` is the one exit and it skips the unreconciled work. The test pins only `rc == 1` and `"REFUSED"` (`tests/context/build/test_reconcile.py:885-902`).

- **High — `context wire` prints `wired: <target>` for installed, deferred, and never-installable targets alike, and the result sticks.** Observed: `_wire_plugin` returns `not install.errors` (`dummyindex/cli/wire.py:239-244`), and the caller prints `wired:` on `True` (`:156-159`). A custom `plugin@marketplace` gets `enabledPlugins=true` with no marketplace source (`dummyindex/context/default_plugins.py:529-548`), then is filtered out of materialisation because only `DEFAULT_PLUGINS` are selectable (`:704-707`). A reviewed default with no `claude` CLI lands in `deferred` (`:739-742`). Both report `wired:`. On the next run `_already_decided` sees the key (`:307-325`), `classify_wired_entry` returns `SATISFIED` (`:465-469`), and `wire` skips the entry (`dummyindex/cli/wire.py:122`). Gap: the output reports success for a plugin that has no source to load from, and the command offers no repair path afterwards.

- **High — headless `context init` enables arbitrary custom `config.wired` targets, contrary to the surface's own description.** Observed: `init` passes the whole post-build `cfg.wired` into declaration (`dummyindex/cli/init.py:70-78`), which writes `enable_plugin` for every absent valid plugin target, reviewed or not (`dummyindex/context/default_plugins.py:539-548`), with no prompt. The wire module docstring says the headless reconciler "classifies and reports … NEVER prompts" and leaves needs-user entries for `wire` (`dummyindex/cli/wire.py:3-8`). Help says the headless reconciler "stays non-interactive; this is the only surface that prompts" (`dummyindex/cli/help.py:665-668`). After init, `wire` classifies the target `SATISFIED` and never shows the confirmation it advertises (`dummyindex/cli/wire.py:109-122`). Gap: the code wins. A committed `attacker@market` entry is enabled without the "untrusted plugin" prompt, and the escalation surface cannot reach it. (`docs/guide/07-cli.md:754-756` makes the same claim but is catalogued `confidence: low`, so it is not quoted as authority.)

- **Medium-high — exit 0 after a reported partial failure, in three handlers.** Observed: `init` prints `plugins warning (…)` to stderr and returns 0 (`dummyindex/cli/init.py:79-84`, `:242`). `wire` prints `could not wire: … (left needs-user)` and returns 0 after the summary (`dummyindex/cli/wire.py:160-162`, `:168-173`). `rebuild --changed` on an enriched index prints `warning: <artifact> failed (…); version stamp not advanced — fix the cause, then run …rebuild --changed` to **stdout** (`dummyindex/context/build/upgrade.py:660-664`, `dummyindex/cli/rebuild.py:157-158`) and returns 0 (`:91-94`). That 0 propagates through `check --auto-refresh` (`dummyindex/cli/check.py:122-126`). Gap: `rebuild --changed` is the documented fix for a stale deterministic artefact, and its exit code cannot tell "refreshed" from "required artefact failed, stamp not advanced", so a scripted caller has to scrape stdout. `plan.md:197-199` lists init and wire as an open question; `rebuild` is not listed there.

- **Medium — `wire` drops the failure reason, re-prompts forever on a marketplace conflict, and mislabels trust.** Observed: `_wire_plugin` discards `declared.errors`, `declared.needs_user` reasons, and `install.errors` (`dummyindex/cli/wire.py:240-244`), so the caller sees only `could not wire: <target>`. For a reviewed default whose marketplace name is already declared with another source, declaration returns needs-user "marketplace … already declares a different source; left unchanged" without enabling (`dummyindex/context/default_plugins.py:536-538`). The key stays absent, so each later run classifies it `ACTED`, prompts again, and fails again with no reason shown. Every prompt is worded `Wire untrusted plugin …` and labelled `untrusted plugin — confirm to wire`, including the reviewed defaults that init's trust disclosure presents as reviewed (`dummyindex/cli/wire.py:200`, `:215`; `dummyindex/context/default_plugins.py:196-214`). The non-TTY branch prints `would prompt:` for every entry in `to_resolve`, including skills and malformed targets that are never prompted (`dummyindex/cli/wire.py:133-134`).

- **Medium — the one-run plugin opt-out neither isolates indexing nor confirms itself.** Observed: `--no-default-plugins` is stripped (`dummyindex/cli/init.py:94-107`), but without `--depth`, `resolve_depth` fully deserialises `config.json` (`dummyindex/context/domains/config.py:542-551`), and a `ConfigError` from any plugin field exits 2 before the build (`dummyindex/cli/init.py:158-165`). The same happens with `--platform agents`. On success the opt-out returns with no output (`dummyindex/cli/init.py:26-27`), and Codex-only init skips the step entirely (`:233-234`). Gap: a recovery run cannot get past unrelated plugin corruption, and a successful run's transcript cannot be told apart from one where the plugin phase never ran. The config gate is in `plan.md:191-196`; the silent success is not.

- **Medium-low — a durable per-target opt-out is reported as enabled.** Observed: `enabledPlugins[target] = false` makes `_effective_enabled` return `False`, which lands in `already` (`dummyindex/context/default_plugins.py:526-528`). `describe_wire_result` renders every `already` entry as `<target> already enabled (left as-is)` (`:296-297`). Gap: the success transcript states the opposite of the effective state.

- **Low — help text contradicts the handler, and a typo'd verb dumps the whole reference.** `scan-check` help says "Exits 0 clean, 1 on violations" (`dummyindex/cli/help.py:245-246`). Warnings-only exits 0 with `ok: true` while `violations[]` still carries the warning rows; only the per-row `severity` tells them apart (`dummyindex/cli/scan.py:69-95`), and help never mentions severity. `maintain --help` prints three stray `gc signal` lines ("one-line nudge iff commits_since … Always exit 0.") under `status` (`dummyindex/cli/help.py:541-545`). Flags are accepted but undocumented: `reconcile --depth` (`dummyindex/cli/reconcile.py:38` vs `dummyindex/cli/help.py:184`) and `query --max-bytes` (`dummyindex/cli/query.py:36-47` vs `dummyindex/cli/help.py:253`). An unknown context verb prints the full `USAGE` to stderr (`dummyindex/cli/__init__.py:155-158`): `dummyindex context grpah` measured 694 lines, with no nearest-match hint and no `usage_error`-style pointer (`dummyindex/cli/common.py:49-63`). That is a large token cost for an agent caller.

Still true at HEAD but not re-listed (owned elsewhere or spec-defended):
- symlinked `.claude/` or `settings.json.tmp` redirecting writes (`dummyindex/context/claude_settings.py:175-179`; Security #1);
- the stale `config.wired` snapshot across prompts (`dummyindex/cli/wire.py:96-166`; Data integrity);
- the `graph` empty-answer exit asymmetry, which is now documented (`dummyindex/cli/graph.py:186-188`, `dummyindex/cli/help.py:285-287`, `spec.md:87-89`).

### Resolved since last review

- `query` no longer folds unknown flags into the search text. It rejects them through `usage_error` (`dummyindex/cli/query.py:84-88`), and every `query` usage failure now carries the `--help` hint (`:40-116`).
- The `query` no-match exit 1 and usage-error exit 2 are documented (`dummyindex/cli/help.py:258-260`).
