## Data integrity

- **[RESOLVED — `outstanding-audit-fixes`]** `confidence.py:56-60` — the two-file confidence mirror was NOT atomic together. `feature.json` was `_atomic_write`-replaced first. Then `_mirror_confidence_to_index` did a separate read-modify-write of `INDEX.json`. A crash between the two `tmp.replace` calls left `feature.json=AMBIGUOUS` with `INDEX.json` at the old value. **Fixed:** both payloads now stage to `.tmp` siblings *before* either replace. They then commit back-to-back in `_commit_confidence_change` (`confidence.py:160-203`). **Residual (documented best-effort, still open by design):** the two `Path.replace` calls are distinct syscalls. A crash *between* them leaves INDEX.json lagging feature.json by one transition. The next run reconciles it, because the mirror is idempotent. The full journal/sentinel crash-reconciliation was left out by design (spec.md "Deliberately left"). Narrowed window, correct ordering, and best-effort docs were delivered instead.
- **[RESOLVED — `outstanding-audit-fixes`]** `confidence.py:91-93` (and `:56-60`) — promote/demote were non-transactional. `del payload[DEMOTED_FROM_KEY]` was committed to `feature.json`, then the INDEX mirror ran separately. A failure after the pop lost the stash permanently. **Fixed:** the stash now pops only from the *staged* payload. INDEX.json stages before either replace. `_commit_confidence_change` stages INDEX first, then feature.json, then replaces back-to-back. A raise before the first replace leaves the on-disk feature.json untouched, stash included. A failure can never strand the feature at AMBIGUOUS with no restore path.
- **[RESOLVED — `outstanding-audit-fixes`]** `confidence.py:108-111` — the INDEX mirror silently no-op'd when the feature_id was absent from `idx["features"]`. A mirror that landed nowhere now surfaces, instead of being swallowed.
- **[RESIDUAL — open]** `confidence.py:205-220` — `_mirror_confidence_to_index` still updates EVERY matching entry without de-dup. - **[RESOLVED — `outstanding-audit-fixes`]** `confidence.py`, `render.py` — JSON was dumped `indent=2` but WITHOUT `sort_keys=True`. That produced noisy no-op diffs on key reorder. **Fixed:** `feature.json` and `INDEX.json` (staged in `_commit_confidence_change` and `_mirror_confidence_to_index`) and `_reality-check.json` (`render.py:18`) now all dump `sort_keys=True`. `render.py` also left the retired local `_atomic_write` for the unified `write_text_atomic` (`render.py:7,19-22`).

- **[RESIDUAL — open]** `confidence.py:90-94` — demote stashes `prior` only when `DEMOTED_FROM_KEY not in payload`. The idempotency early-return at `:88` only catches an already-AMBIGUOUS feature. The prefix is kept here and stripped later in verify by `_bare_name`. But two genuinely different prose claims `\`A\` calls \`b\`` and `\`a\` calls \`B\`` collapse to one verdict. ## Security

- **[RESOLVED — `outstanding-audit-fixes`]** `verify.py:157-202` (`_resolve_cited_path`) — **doc-controlled path traversal / arbitrary file read**. `path_str` comes from a doc citation parsed by `_FILE_LINE_RE` (`extract.py:32-34`). That regex permits `../`. The resolver joined `repo_root / path_str` with **no containment check**. The line-count verdict became an oracle over arbitrary host files. **Fixed:** every concrete-path return branch of `_resolve_cited_path` now routes through `_confine` → `resolve_under_root` (re-exported from `pipeline/io`). It checks against `repo_root`, or `feat_dir` for the feature-own-doc branch (`verify.py:195-264`). An out-of-root path (absolute, `../` escape) yields a `("contradicted", "cited path resolves outside the repository root")` verdict. The file is never opened. Note: `_FILE_LINE_RE` requires a `.ext` before `:line`. Extensionless paths like `/etc/passwd:1` are grammar-rejected upstream. The confinement test must use extension-bearing proof strings. **Residual (symlink-swap, documented):** the symlink resolves *before* the confinement check. An in-root symlink is legitimate. An escaping one is contradicted. A post-resolution symlink swap (TOCTOU between `resolve_under_root` and the `open`) remains a documented residual. It is accepted as out of scope for a local-dev auditor.
- **[RESOLVED — `outstanding-audit-fixes`]** `verify.py:63` + `_repo_root_from_meta` — **`repo_root` was taken verbatim from unvalidated `meta.json["root"]`** (`Path(_repo_root_from_meta(...) or context_dir.parent)`). A poisoned `meta.json` setting `root` to `/` turned every citation into a whole-filesystem read oracle. **Fixed:** `reality_check_feature` now anchors `repo_root` via `_trusted_repo_root` (`verify.py:468-488`). The trusted anchor is the **resolved git toplevel** (`_git_toplevel` via `is_git_repo`/`resolve_git_dir`, `verify.py:437-455`). It is *not* "any ancestor of `context_dir`", which admitted `/`. `meta.json["root"]` is honored only when it resolves to exactly that toplevel. The check compares resolved paths, not strings. Otherwise it falls back to the anchor. With no git toplevel at all, it falls back to the historical `context_dir.parent`. A nested-`.context/` fixture (where `context_dir.parent` is not the repo root) with a real `.git` exercises the non-trivial case.
- **[RESOLVED — `outstanding-audit-fixes`]** `cli/reality_check.py:39` + `verify.py:30` — **feature-id path injection via `--feature`** turned an unsanitised id into a write primitive. The primitive was `write_report` or a confidence mutation, outside `features/`. **Fixed:** the id is rejected at the **CLI boundary** (`cli/reality_check.py:50-57`, non-zero exit, before any read or write). It is also rejected inside the verifier via `_reject_unsafe_feature_id` (`verify.py:36-49`, raises `ValueError`). Both reject any `/`, `\`, `..`, or NUL. Defence in depth: neither entry point trusts the value.
- **[RESOLVED — `outstanding-audit-fixes`]** `verify.py:143-146` — **no size / symlink / file-type guard on the read target**. `sum(1 for _ in resolved.open("rb"))` streamed the entire file. A multi-GB blob, FIFO/device, or symlink into `/proc` caused unbounded read or hang. **Fixed:** before the line-count read, the resolved path passes `is_safe_read_target(resolved, max_bytes=_MAX_CITED_FILE_BYTES)` (16 MiB, `verify.py:175-180`). A symlink (`S_ISLNK`), non-regular file, or oversize blob yields `ambiguous` ("cited path is not a safe regular file to read"). It is never streamed.
- **[PARTIALLY RESOLVED — `outstanding-audit-fixes`]** `confidence.py:97-111` — **a poisoned doc can silently demote a feature's confidence**. The *silent* half is fixed. `--demote` now prints the confidence delta (`demoted/restored/unchanged`) at the CLI. It comes from the widened `ConfidenceTransition | None` return (`cli/reality_check.py:76-89`, `confidence.py:42-54`). The mutation is no longer invisible. **Residual (open, by threat model):** `--demote` still flips on `report.has_contradictions`, which an attacker-authored false claim can force. The path-confinement and trusted-root fixes above now gate the underlying trust-signal-tampering exposure. A poisoned doc can no longer also leak host files. A false demote from an in-repo false claim is still possible. It is acceptable only if the upstream docs are treated as trusted input. The demote remains idempotent and reversible.

- **[RESOLVED — `outstanding-audit-fixes`]** caller runs `reality-check --feature X --demote` on docs they have fixed. - caller cites `` `models.py:7` `` and the file exists with ≥7 lines. Verdict: "verified" (`verify.py:143-152`). Gap: verification counts lines and never reads line 7's content. Any in-range number "verifies". An edit that shifts the symbol off line 7, but keeps the file long enough, still passes. The `file:line` verdict means "this file is at least N lines", not "the cited thing is at line N".
- caller writes `` class `Claim` has method `to_dict` `` — verdict "verified" iff both `Claim` and `to_dict` exist as symbols anywhere in the map (`verify.py:115-123`). Gap: no ownership check. `to_dict` is a method on several frozen dataclasses. A claim binding it to the wrong class still verifies. Conversely, the "contradicted" branch fires when either name is merely absent from the map. A renamed class, or a method indexed under a different name, reads as a hard contradiction (false positive). On `--demote`, that flips the feature to AMBIGUOUS over a naming mismatch, not a real lie.
- caller relies on the report to decide the council exit gate. Exit code is `1 if report.has_contradictions else 0` (`cli/reality_check.py:75`), driven solely by `contradicted > 0` (`models.py:43-44`). Gap: ambiguous verdicts (external refs, missing call edges, multi-match basenames; `verify.py:99,110,198`) never affect exit code or trigger demotion. A doc that is entirely unverifiable-but-suspicious passes the gate exactly like a verified one.
