## Product surface

- **High. Upgrade from an install older than 0.36.0 (no `.dummyindex-files.json`, stamp ≠ `0.36.0`) is a permanent exit 1.** `_baselines` returns `{}` unless the stamp equals `LEGACY_VERSION` (`dummyindex/installer/ownership.py:100-116`, `dummyindex/installer/legacy_fingerprints.py:7`). Every existing file whose bytes differ from the current render is therefore kept as preserved (`ownership.py:197-202`), and that includes each `SKILL.md` in 9 of 10 families, because each one embeds `__VERSION__`. The family stays `complete: false` and its stamp does not advance (`ownership.py:217`, `234-238`). The `older` stamp still makes it a repair candidate, labelled "per-file ownership checks preserve edits" (`dummyindex/installer/repair.py:680-686`), although no edits exist. The repair then raises "preserved customized or unproven files" (`repair.py:476-487`). The Claude side prints `claude family preserved (repair failed; see diagnostic)` (`dummyindex/installer/install/orchestrate.py:220-221`), and the run ends with `error: partial installation; … before retrying` and exit 1 (`orchestrate.py:357-362`). The manifest written by that run records only the files that matched, so every retry repeats the same result. `uninstall` deletes only those matched files and prints `skill preserved` for the rest (`ownership.py:263-276`; `dummyindex/installer/uninstall.py:185-188`). No flag adopts the old content: `--force-downgrade` bypasses the stamp, not the hashes (`ownership.py:171-178`). Deleting the directories by hand is the only way out, and nothing in the CLI output names that step.
- **High. Defaults combined with the plugin opt-out store an opt-in.** `install --defaults --no-default-plugins` on a repo with no config takes the early return in `_wire_default_plugins_step` (`dummyindex/installer/install/project_init.py:328-329`). Then `_write_default_config` writes `default_config(platform)` (`orchestrate.py:333-334`; `project_init.py:252-276`), which sets `default_plugins_enabled: true` and lists all three defaults in `wired` (`dummyindex/context/domains/config.py:446-447`). The next bare `install`, which is the `/dummyindex-update` path, reads that config and enables and installs the three plugins the user declined (`project_init.py:368-376`). `--no-default-plugins` used alone prints no line. On Claude installs it also skips the config schema migration and the equipped-plugin fold (`project_init.py:356-357`; `orchestrate.py:338`). `--help` mentions neither effect, and it gives `--no-superpowers` as an alias that silences all three defaults (`dummyindex/installer/args.py:43-44`). The durable opt-out, `default_plugins_enabled: false` (`config.py:621`), has no CLI writer, and `enabledPlugins: true` values written earlier stay in place.
- **High. Uninstall leaves state that keeps running.** `uninstall()` removes skill families, family links, thin references, `/tokens` and Codex guidance (`uninstall.py:20-133`). Nothing under `dummyindex/installer/` calls `hooks.uninstall` (`dummyindex/context/hooks.py:617-688`), so the five hook events stay in `<repo>/.claude/settings.json`.
  - The first UserPromptSubmit command runs `printf` then `exit 0` with no `command -v dummyindex` check (`hooks.py:120-131`; the reason is given at `384-388`). The always-on reminder therefore keeps being injected after the CLI is removed, and also for teammates who never installed it.
  - `statusLine` has no remover. Its command has no check either (`hooks.py:311-315`). The next install puts back a status line the user deleted by hand, and a `null` value counts as unset (`hooks.py:309-310`, `336-343`, `362-370`). The only lasting opt-out is to configure a different status line.
  - The `~/.claude/CLAUDE.md` block (`orchestrate.py:384-396`) has no removal step in `uninstall.py`. It is also never refreshed, because the "already registered" test is a substring match (`orchestrate.py:388-390`).
  - `install --platform claude` in AUTO mode also writes the 10 `.agents/skills` families (`orchestrate.py:95-97`). `uninstall --platform claude` removes only the Claude side (`uninstall.py:54-57`), which leaves bodies that every Agent-Skills host still discovers.
  - `_UNINSTALL_USAGE` mentions only "project guidance and hooks" (`args.py:55-58`). It leaves out `statusLine`, `enabledPlugins`, marketplace declarations, the global CLAUDE.md block, the leftover `.agents` tree and `.context/`. It also does not point to `dummyindex context hooks uninstall` (`dummyindex/cli/hooks.py:85-93`).
- **Medium. `dummyindex install` reports less about hooks than `context hooks install` does.** `_install_project_hooks` prints `installed:`, or else `already current (N)`, plus warnings (`project_init.py:241-247`). It never reads `HookResult.refreshed` or `nudges` (`hooks.py:447-466`), although `cli/hooks.py:69-73` and `80-81` print both. On an upgrade that rewrites hook bodies in place (`hooks.py:541-549`), the run prints `already current (k)` for the untouched subset, or nothing at all, although the git-tracked `settings.json` changed. Avoiding that kind of report is the stated reason `refreshed` exists (`hooks.py:451-455`). The advisory for an unparseable `settings.json` (`hooks.py:321-326`, `557-560`) prints nothing, and neither does a badge skipped because the user already has a status line (`hooks.py:362-364`). Deleting a legacy `.git/hooks/post-commit` or `PostToolUse` entry (`hooks.py:509-517`, `523-525`) prints nothing through either command, since neither prints `removed` (`project_init.py:241-247`; `cli/hooks.py:66-84`). A failed hook install never changes the exit code (`project_init.py:236-249`).
- **Medium. Exit codes and verification do not match what happened.**
  - A healthy link whose renamed-aside `tmp_old` could not be deleted produces an extra `skipped` line on every run where `_recover_leftover_temp_artifacts` fails again (`dummyindex/installer/link/create.py:286-300`, `304-326`, `567-568`). Any `skipped` line sets `complete = False` (`orchestrate.py:275-278`), so install exits 1 with "edited, unproven or failed families were preserved" (`orchestrate.py:357-361`), even though no family was preserved.
  - `uninstall` prints only `removed[0]` (`uninstall.py:130-133`) and exits 0 even when every family was preserved (`uninstall.py:187-188`; `dummyindex/__main__.py:325-328`).
  - `check --versions` returns 0 on version skew and on source warnings (`dummyindex/cli/check.py:293`, `359`). It labels Claude rows only as `(linked)` or `(materialized link…)` (`check.py:224-233`). A thin-reference layout, which is what AUTO produces on Windows without symlink rights, therefore looks the same as a full copy.
  - `dummyindex status` reports no hook state, statusLine, install scope or layout (`dummyindex/cli/status.py:39-82`).
- **Medium. A downgrade gives the wrong reason on the agents side.** When the installed CLI is older than the families' stamp, the Claude side prints a specific line, `claude family preserved (newer or unknown version; --force-downgrade required)` (`orchestrate.py:212-226`). The `.agents` side instead goes through `_install_skill_family`. `sync_family` returns every file as preserved (`ownership.py:171-178`), and the loop prints `codex skill installed -> …` for each of the 10 families, followed by `skill preserved -> <file> (edited or unproven)` for about 48 files (`dummyindex/installer/install/family_write.py:86-88`). Neither label is accurate. The real cause appears only on the repair report line printed before those (`repair.py:701-706`, rendered at `627-632`).
- **Medium. Hidden costs on every run.**
  - Every Claude install with the defaults enabled starts up to 6 `claude` subprocesses, each with a 60 s timeout: `--version`, then `marketplace add` and `plugin install` for each of the two third-party defaults, and `plugin install` for superpowers (`dummyindex/context/default_plugins.py:586`, `637-673`, `739-752`). This happens again on every rerun, because a target that is already `true` stays eligible (`default_plugins.py:711-728`). The only no-network switch is `DUMMYINDEX_SKIP_PLUGIN_INSTALL` (`default_plugins.py:113-117`, `735-738`). It is missing from `_INSTALL_USAGE` (`args.py:10-50`) and from the trust line, which offers only `--no-default-plugins` (`default_plugins.py:211-212`).
  - Every session runs 4 SessionStart commands (`hooks.py:147-198`). The `plan-update` drift body has no size limit and no shorter-output flag (`dummyindex/context/drift.py:268-306`; `dummyindex/cli/plan_update.py:68-100`). The only way to quiet it is to remove all five events (`cli/hooks.py:85-93`).
- **Low. Flags that do nothing, and the old `codex` name showing through.**
  - With `--skill-only`, the flags `--defaults` and `--no-default-plugins` are parsed and then have no effect, and nothing warns about it (`orchestrate.py:325-334`).
  - `--copy --platform agents` is silently ignored, while `--link --platform agents` exits 2 (`args.py:191-203`; `orchestrate.py:227`).
  - `--force-downgrade` also lowers `meta.dummyindex_version` (`project_init.py:86-91`), but its help mentions only skill copies (`args.py:47-48`).
  - `install(platform="agents")` exits 1 with `platform must be claude|codex|both` (`orchestrate.py:89-93`; `dummyindex/installer/common.py:145-152`), while `uninstall()` normalizes the same value (`uninstall.py:41-45`).
  - After `--platform agents`, the no-repo hint tells the user to run `dummyindex ingest <path> --platform codex` (`orchestrate.py:374-380`). That is the deprecated spelling, and `ingest` sends it through `normalize_platform_arg` (`dummyindex/cli/init.py:128-132`), which prints the deprecation warning (`common.py:177-184`). Doc conflict, code wins: the shipped update skill (catalogued `low`) also tells the agent to pass `--platform codex` (`dummyindex/skills/update/SKILL.md:110`, `122`).

### Resolved since last review

- `--defaults` vs `--no-onboarding`: the help now documents `--defaults` as an alias (`args.py:41-42`), and the plan no longer mentions any way for the two to diverge.
- "Install mode not reported anywhere": `check --versions` now labels linked Claude rows (`check.py:224-233`, `329-336`). The reference layout is still unlabelled; that gap is in the exit-codes bullet above.
- The `--dedupe` "no dry-run" claim no longer holds: the help scopes the flag to "the named scope (report-only without this flag)" (`args.py:45-46`), and a run without the flag lists duplicates (`repair.py:633-638`).
- The "eight `claude skill migrated` lines" count is now 10, one per family (`common.py:89-99`).

Not carried forward, though still true: the `uninstall --platform agents` restore hint (`uninstall.py:81-101`), which was a positive note; and the 10-tuple slot order (`args.py:207-218`), which callers cannot see.
