## Product surface

Paths follow `plan.md` shorthand: leading `dummyindex/` dropped; `equip/` = `context/domains/equip/`. Reconciled at HEAD `0634bfd`. `skills/equip/SKILL.md` and `skills/build/SKILL.md` are catalogued `low` and appear below only as conflict flags, never as authority.

- **`equip patch` on a hand-edited body takes ownership of it.** Observed: `apply_patch` gates only on `is_lifecycle_managed` (`equip/lifecycle/evolve.py:41-43`; predicate at `equip/lifecycle/status.py:77-89`) and never calls `classify_item`. It rewrites whatever is on disk and re-baselines `origin_hash` (`equip/lifecycle/evolve.py:58-71`). `classify_item` returns PRISTINE on a hash match before it checks invariants (`equip/lifecycle/status.py:161-167`), so a USER_MODIFIED body becomes equip-owned, and an INVARIANT_BROKEN body loses its alarm. Apply refuses that laundering ("so an INVARIANT_BROKEN alarm is not laundered to PRISTINE here", `cli/equip/dispatch.py:493-504`). Evolve promotion also refuses it: "managed capability was edited outside evolve" (`context/domains/evolve_gate.py:306-309`). **Gap:** the CLI patch writer does not follow the rule that `plan.md:64-67` ("user-owned bodies are never rewritten or re-baselined") and `plan.md:75-76` ("a second writer under the same rule") claim. None of the five tests in `tests/context/domains/equip/test_equip_evolve.py:56-117` patches an edited body. Plan/code conflict: the code wins.

- **`--platform claude` pointers carry no tool limits and no trigger text.** Observed: templates declare per-role tools: reviewer `Read, Bash, Grep, Glob` (`skills/equip/templates/reviewer-agent.md.tmpl:4`), performance without `Write`, docs without `Bash` (`…/performance-specialist-agent.md.tmpl:4`, `…/docs-specialist-agent.md.tmpl:4`). Render strips that line with the comment "Tool permissions belong to native adapters" (`equip/generate/plan.py:85-86`). `native_adapter_content` emits only `name` and `description: Use the project's {name} capability.` (`equip/generate/adapters.py:33-42`). The manifest's only tool field, `required_tools`, records toolchain binaries, not permissions (`equip/generate/plan.py:124-135`). The template's "Use after…" trigger sentence survives only in the canonical body (live: `.context/equipment/dummyindex-reviewer.md:3`). Pointer writes are neither printed nor counted: only warnings are printed (`cli/equip/dispatch.py:669-687`), and neither the summary line nor the JSON has an adapter count (`cli/equip/dispatch.py:689-710`). **Gap:** no emitted artifact holds a read-only reviewer's restriction, and a host's native frontmatter gets a description that names the agent and nothing else. A native-migration failure is counted under `preserved N user-modified` / `preserved_user_modified` (`cli/equip/dispatch.py:576-581`), even though the canonical body was already written at `:551` while the record keeps the old path.

- **An edited body that survives `uninstall` is cut off from the lifecycle on the next `apply`.** Observed: `uninstall` keeps user-owned bodies and prints `kept NAME (user-modified)` (`equip/lifecycle/status.py:379-382`, `cli/equip/verbs.py:258-259`), then deletes the manifest (`equip/lifecycle/status.py:427`). Its native pointer stays too, because `continue` precedes `remove_native_adapter` (`:380-394`). The next `apply` finds `prior_item is None`, prints `skip NAME -> … (existing user file, not ours)` and appends no record (`cli/equip/dispatch.py:526-540`). With no record, or a record that names another path, an unedited CRLF copy hits the same skip, because `_matches_content` compares raw bytes (`cli/equip/dispatch.py:723-727`; open question at `plan.md:94-96`). **Gap:** the file that one verb called "kept" the next calls "not ours". After that, `status`, `refresh`, `reset`, `patch` and `remove` cannot reach it, because each needs a record (`equip/lifecycle/status.py:198-206`, `:340-342`; `equip/lifecycle/evolve.py:41-43`; `equip/lifecycle/remove.py:57-60`). Build dispatch, which reads only the manifest (`cli/build_loop/waves.py:157-183`), drops the capability. No verb re-adopts the file. The only recovery is to move it away, and then `apply` regenerates the stock body.

- **The overwriting verbs have no preview, and the preview that exists under-reports.** Observed: `run_reset`, `run_remove` and `run_patch` parse no `--dry-run`. In each, the flag lands in `leftover` and the verb returns 2 (`cli/equip/verbs.py:142-152`, `:186-206`, `:266-274`). `uninstall --dry-run` always prints `removed hook event(s): []`, because events are computed only when `not dry_run` (`equip/lifecycle/status.py:416-426`). Its "removed N file(s)" count includes marketplace plugins (`:402-405`), and the manifest deletion (`:427`) is never printed (`cli/equip/verbs.py:252-259`). `refresh` rewrites `.context/equipment.json` on a metadata-only change (`equip/lifecycle/status.py:282-296`, `:313-316`) while printing `refreshed 0` (`cli/equip/verbs.py:46-53`). It also exits 0 with an INVARIANT_BROKEN alarm (`cli/equip/verbs.py:132-136`). An empty `status` advises "run `equip` first" (`cli/equip/verbs.py:99-101`), and bare `equip` exits 2 (`cli/equip/dispatch.py:106-111`). **Gap:** `reset` overwrites an edit and `remove --delete-file` deletes a file, both with no preview or backup. The only preview the CLI has does not show hook removal or registry deletion. (`skills/equip/SKILL.md:80-82,460-461` require a dry-run before `reset`/`patch`. The doc is catalogued low and the code wins.)

- **Deleting a generated specialist does not decline it.** Observed: `build_catalog` passes every templated capability on every pass (`equip/generate/catalog.py:61-71`, `:97-108`). `refresh` reports `skipped(missing)` and leaves the file absent (`equip/lifecycle/status.py:257-260`). `apply` treats MISSING like PRISTINE and rewrites the file (`cli/equip/dispatch.py:516-525`, `:551`). `remove NAME --delete-file` drops the record and the file (`equip/lifecycle/remove.py:63-82`), and the next `apply` recreates both. **Gap:** `EquipmentItem` has no decline field (`equip/models.py:83-108`) and no flag excludes a template. The only change that sticks is editing the body into a no-op so the hash baseline freezes it.

- **After a project rename or stack re-detection, the old record reads as current.** Observed: `apply` carries the old-named record forward and prints `keep NAME (generated record not re-rendered this run — carried forward)` (`cli/equip/dispatch.py:641-654`). This mitigates the problem only partly. `specialist_caps_from_manifest` forces the stale specialists' capabilities (`cli/equip/common.py:115-133`), so the new-slug twins render alongside them. `refresh` files a record with no fresh render under `unchanged` (`equip/lifecycle/status.py:272-275`), `status` shows it `pristine` (`:199-200`), and `reset` refuses with `not a generated item in the current catalog` (`cli/equip/verbs.py:162-167`). **Gap:** old and new records with identical capabilities both enter the dispatch pool (`cli/build_loop/waves.py:174-183`). `refresh`/`status` give the orphan the same label as a current item. Only `remove NAME --delete-file` clears it, and only for a caller who already knows the stale name.

- **A stale hook record is invisible.** Observed live: `.context/equipment.json` holds `ruff-format` at `.claude/settings.json`, while `.claude/settings.json` contains 0 `DUMMYINDEX_EQUIP` entries. `status` prints no row for it, because the record is neither lifecycle-managed nor MARKETPLACE/INSTALLED (`equip/lifecycle/status.py:84-89`, `:198-206`). Hook records are re-derived only when `native_claude` is set (`cli/equip/dispatch.py:615-636`). A default `--platform agents` apply therefore carries the record forward on every run, under the label `generated record not re-rendered this run` (`cli/equip/dispatch.py:643-654`). `remove ruff-format` drops the record and leaves any settings entry in place (`equip/lifecycle/remove.py:13-14`). **Gap:** the registry asserts a wired hook that does not exist, and no verb reports the mismatch.

- **The formatter hook can no-op silently on every edit.** Observed: detection prefixes `uv run ` for uv repos (`equip/generate/detect.py:124`). The hook strips that prefix, then guards with `command -v ruff >/dev/null 2>&1 || exit 0` and suppresses failures with `2>/dev/null || true` (`equip/generate/catalog.py:172-179`). On a uv repo whose `ruff` is only in the project venv, the guard therefore exits 0. The path comes only from `"$CLAUDE_FILE_PATHS"`. The hook never reads the hook payload, and the tests assert only the literal string (`tests/context/domains/equip/test_equip.py:429`). `wire_hooks` adds its entry without checking existing PostToolUse entries for an equivalent formatter (`equip/wiring/hooks.py:44-55`). **Gap:** `apply` reports `wired 1 hook event(s)` (`cli/equip/dispatch.py:703-710`) for a hook that fails quietly in each of these cases, and nothing surfaces whether it has ever formatted a file.
