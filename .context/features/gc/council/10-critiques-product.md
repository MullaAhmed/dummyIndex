# Product surface — gc (critic-product, stage 3)

## Product surface

- Fresh repo, nobody has swept yet — anchor unset → `commits_since=None` (`git_delta.commits_since` returns `None` when `anchor is None`) → `should_signal=False` (`scan.py:58`); the only writer of the anchor is `stamp_gc` (`anchor.py:126-143`), whose only caller is `gc stamp` (`cli/gc.py:166`) — the SessionStart nudge whose job is to trigger a first sweep only arms *after* a sweep already ran; this repo's own `.context/gc/` is an empty directory with no `state.json`, so its nudge has never fired once.
- Deleting an archived child the way the skill documents — `SKILL.md:51` lists "an `_archive/*` child" as a dead doc removed via step 5's `gc delete --kind proposal --slug <slug>`, but a slug target resolves to `root / slug` = `proposals/<slug>` (`delete.py:96`) — observed on a probe repo: `gc delete --kind proposal --slug old-plan --yes` printed `context gc delete: nothing to delete`, exit 0, with `proposals/_archive/old-plan` still on disk — the skill's only documented delete path for archived candidates is a silent success-shaped no-op.
- Caller retries with the kind the report gave them — `gc status --json` emits `"kind": "archived"`, and `_resolve_kind` (`cli/gc.py:271`) rejects it with `--kind must be proposal|audit` — no flag combination shown anywhere in `SKILL.md`'s CLI reference deletes an archived candidate.
- Caller copies `rel_path` out of the status report into `--path` — `target = Path(path)` is cwd-relative (`delete.py:94`) — observed: `--path proposals/_archive/old-plan` → `error: refusing to delete ...: resolves outside root .../.context/proposals`, exit 2 — the report's only location field is not accepted by the only verb that consumes locations; the caller must hand-prefix `.context/` or pass an absolute path.
- `--path` aimed one segment short of an archived child — sentinel-reject runs only under `if safe_slug is not None` (`delete.py:88-89`), so a `--path` target is never sentinel-checked — observed: `--kind proposal --path <abs>/.context/proposals/_archive --yes` printed `removed`, exit 0, and every archived child went in a single `rmtree` — `--path` is the *only* route to an archived child, and the adjacent typo is an unwarned bulk wipe of the archive; `plan.md:133-136` claims `--path` "the realpath guard contains", which is true of escapes but not of the container itself (code wins).
- Rehearsing a delete before the step-4 confirm — `cli/gc.py:127-130` prints the dry-run line and returns before any domain call — observed: a nonexistent slug and an untracked workspace that the real run refuses both print the identical `would delete ...` line — the dry run predicts neither existence nor any guard outcome, so every refusal surfaces only *after* the user has already confirmed the item.
- A confirmed untracked workspace hits the recoverability guard — `delete_workspace` returns `refused=True` and the CLI prints `refused — unrecoverable: not tracked by git` at **exit 0** (`cli/gc.py:147-151`) — observed `real exit=0`; a refusal and a completed deletion are indistinguishable by exit code to any loop or wrapper driving step 5.
- Council reads signals for an archived candidate — `signals.py:63-64` probes `proposal_dir(context_dir, slug)` = `proposals/<slug>` while `enumerate.py:98` places the workspace at `proposals/_archive/<slug>`, and `_walk_archive` hardcodes `status=None` (`enumerate.py:99`) — observed: an archived proposal carrying `{"status":"done"}` and a `plan.md` reported `[age-0d]` and nothing else — archived candidates can never emit `status:`, `orphan-empty`, or `checklist-*`, which are exactly the tags step 3's categories key on.
- Freshly scaffolded, not yet committed proposal — `_make_candidate` computes `age_days` only `if tracked` (`enumerate.py:156`) — observed `"age_days": null` with the `untracked` tag — the age evidence is missing precisely for the workspaces most likely to be orphan scaffolds.
- Consumer filters the documented `kind` alphabet on `orphan_scaffold` — `CandidateKind.ORPHAN_SCAFFOLD` is declared (`enums.py:28`), included in `_PROPOSAL_KINDS` (`delete.py:56`), and named in `_resolve_kind`'s docstring (`cli/gc.py:265`), but no code path constructs it (`enumerate.py` emits only `proposal`/`archived`/`audit`) — the filter matches nothing; orphan-ness only ever arrives as the `orphan-empty` *signal*, so the enum hints at a capability the walk does not deliver.
- Conductor looks for the published verdict vocabulary — `Disposition` is exported from the domain (`enums.py:8-21`, `keep/delete_doc/delete_code/route_to_proposal`) and never constructed in Python, while the skill's step-2 verdicts are `keep/stale/superseded/dead` (`SKILL.md:43`) — the only published disposition alphabet and the only one actually used do not match, and nothing validates the skill's.
- Conductor filters `signals` for `ARCHIVED` as `SKILL.md:31` lists it among the example tags — `classify` never emits it (`signals.py:38-80`); `archived` is a `kind`, not a signal — the documented tag set overstates what the report contains.
- Repo wants a different sweep cadence — `DEFAULT_COMMIT_THRESHOLD = 10` is a module constant (`constants.py:27`); `scan` and `should_signal` accept `threshold=` but no caller passes it, and neither verb parses a flag for it (`cli/gc.py:61,184`) — observed: `gc status --threshold 3` → `error: unknown argument: --threshold`, exit 2 — tuning the only proactive surface requires editing source.
- User sees the nudge and declines the sweep — the memo is fire-once *per session* (`anchor.py:120-123`), so the nudge returns on every new session until the anchor advances, and `gc stamp` is reachable only as step 6 of the full sweep (`SKILL.md:82-88`) or by hand — there is no snooze/dismiss short of stamping, and stamping records that the repo was swept when it was not.
- User expects "clean up dead context" to cover generated `.context/` workspaces (`spec.md:7`, skill description) — `enumerate_candidates` walks only `proposals_root` and `audits_root` (`enumerate.py:55-58`) — this repo carries 28 generated `features/*/council/` stage-artifact dirs plus `equipment-evals/`, none of which can ever appear as candidates; the sweep's stated scope is wider than its walk.
- Sweep confirms N dead docs at step 4 — `delete_workspace` takes one target and `_parse_flags` supports no repeatable flags ("gc has none", `cli/gc.py:310-311`) — N confirmed items are N invocations each printing one line, with no batch verb, no run summary, and no record of what a sweep removed beyond the anchor sha.
- Codex user relies on the throttle — `hooks.py:170-184` wires `gc signal` into Claude's SessionStart only, and `SKILL.md:31` states "Codex installs no dummyindex GC hook" — the identical throttle state is computed on both hosts but only surfaces unprompted on Claude; a Codex caller only sees it by remembering to run the sweep the nudge exists to prompt.
- User reads `gc status` after the session's nudge already fired — status recomputes the pure predicate and never consumes the memo (`scan.py:58`) while `signal` consumes it (`anchor.py:120-122`) — `should_signal=true` is shown for a probe that will stay silent for the rest of the session; the divergence is recorded in `plan.md:101-105` but invisible in either verb's output.
