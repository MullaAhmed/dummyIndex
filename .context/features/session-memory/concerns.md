## Data integrity

- `memory/breadcrumb.py:49-52` — the "newest section is already a breadcrumb → replace it" branch checks only `AUTO_BREADCRUMB_TAG`, never the date or session, and `roll_tiers` is wired to **no hook** (only `dummyindex/skills/memory/SKILL.md:30`, i.e. the agent running `/dummyindex-remember`), so for the exact user who relies on breadcrumbs — the one who never saves a handoff — every PreCompact silently destroys the previous day's and every concurrent session's breadcrumb, leaving exactly one auto-entry ever — compare `section_date(sections[0].heading)` against `now.date()` (and the session id) and prepend rather than replace when they differ.
- `memory/roll.py:84-98` — the tier cascade is three independent `write_text_atomic` calls with the *delete* side ordered first (`now.md` minus `now_down` at `84-88`, then `recent.md` plus `now_down` at `89-93`), so any crash, OSError, or SIGKILL between them permanently loses the relocated sections with no tmp file left to recover from — invert to archive → recent → now so an interruption duplicates instead of deletes, and make the re-run drop already-present sections.
- `memory/roll.py:39-41,74` + `memory/parse.py:21,52-55` — `_DATE_RE` accepts any `\d{4}-\d{2}-\d{2}` including non-constructible dates, so a heading containing `2026-13-45` (or a ticket/version token of that shape) makes `_ordinal` raise `ValueError` out of `roll_tiers` into `cli/memory.py:174`, which has no try/except; worse, `_is_before_today` compares strings so the bad section first *moves down* into `recent.md` and then breaks every subsequent roll — have `section_date` return `None` when `date(...)` cannot be constructed, so malformed text is treated as undated.
- `memory/emit.py:40-60` — `now` is inlined in full while `recent` is capped at `_RECENT_HEAD`, and the `max_chars` cut at `59-60` truncates from the end, so once `now.md` passes ~3.9 KB the SessionStart block silently drops `core-memories.md` — the one tier that is never rolled and is meant to be durable — apply `_head` to `now` as well and reserve a fixed budget for `core` before truncating.
- `memory/breadcrumb.py:47-54`, `memory/nudge.py:60-67`, `memory/roll.py:64-98` — every store mutation is an unlocked read-modify-write, while `domains/atomic_io.py:14-18` explicitly documents that two Claude profiles hit the same repo concurrently; `write_text_atomic` prevents a *torn* file but not a *lost update*, so a breadcrumb written between another session's roll-read and roll-write vanishes — guard read-modify-write on the tier store with an `O_EXCL` lock file (the pattern already exists at `context/output/bootstrap.py:499`).
- `domains/atomic_io.py:22-31` — no `flush`/`os.fsync` on the handle before `replace` and no parent-directory fsync, and the tmp sibling is unlinked in `finally`, so a power loss mid-write can leave a zero-length `now.md` with nothing to recover from; this is the git-committed, user-owned half of the store, and the repo lives on a mounted Windows filesystem where rename-after-content ordering is weaker than ext4's — fsync the handle before close and the directory after `replace`.
- `domains/atomic_io.py:22-29` — `NamedTemporaryFile` creates the replacement at `0600` and no mode is copied from the original, so every `.context/session-memory/*.md` and cache file silently loses group/other read permission on its first rewrite (invisible in git, which tracks only the exec bit) — `os.chmod` the tmp to the pre-existing file's `st_mode`, falling back to `0o666 & ~umask` for a new file.
- `miner/pipeline.py:146-152` + `miner/feedback.py:112-133` — `refresh_skill_feedback` discards the `bool` from `write_skill_feedback`, which returns `False` on *every* `OSError` (`117`, `131-132`), and `cli/memory.py:87-94` swallows whatever escapes, so an unwritable `.context/cache/` makes `memory mine` a permanent silent no-op that still returns a populated tuple to its caller — propagate the write outcome and surface it on the non-hook invocation path.
- `miner/feedback.py:113-128` — the write path `lstat`s for symlink/regular but, unlike `read_skill_feedback:143-152`, never checks `st_size` before the `path.read_text()` comparison, so a corrupt or oversize `skill-feedback.json` is decoded into memory in full on every SessionStart — apply the same `MAX_CACHE_BYTES` guard before the comparison read.
- `miner/pipeline.py:112-137` + `miner/corrections.py:269-283` — the cache is a pure projection recomputed from whatever transcripts still exist, with no decay and no durable record, so when the host prunes old JSONL the count falls back below `DEFAULT_MIN_SKILL_CORRECTIONS` (`miner/enums.py:38-40`) and an established skill preference silently disappears; the derived state is non-monotonic in a way no consumer can detect — persist first-seen/last-seen counters in the cache and threshold on those instead of on live transcript availability.
- `memory/parse.py:35-42` — `split_sections` treats any line beginning with `## ` as a boundary with no fenced-code awareness, so a handoff containing a markdown example splits into two sections that `roll_tiers` can then send to *different* tiers, severing a fence and orphaning half an entry — track ` ``` `/`~~~` fence state while scanning.
- `memory/parse.py:40,48,70` — the split/render round-trip is lossy (bodies get `.strip("\n")`, sections are re-joined with exactly one blank line), so a roll silently rewrites the formatting of user-authored entries it did not move, contradicting the byte-faithful contract `write_text_atomic` promises at `domains/atomic_io.py:41-45` — preserve each section's original inter-section whitespace, or state the normalization as the store's contract.
- `memory/nudge.py:38-46,60-67` — `_load_state` validates only that the top level is a `dict`, then `mark_nudged` calls `kv[1].get(...)` on every value, so one non-dict entry raises `AttributeError` through the NUDGE verb, which — unlike MINE and PROMPT_CONTEXT — has no try/except (`cli/memory.py:130-142`), breaking the "a Stop hook must never fail the turn" guarantee asserted on line 142; identical shape at `context/reconcile_gate.py:255-263` — drop non-conforming entries on load, matching the fail-closed validation `miner/feedback.py:136-200` already applies to the sibling cache.
- `memory/roll.py:79,94-98` + `memory/emit.py:40-42` — `archive.md` is append-only with no tier below it and **no reader** (emit consumes now/recent/core only), yet it is git-committed (`.gitignore:19` covers only `.context/cache/`), so it grows without bound in every consumer repo — bound it by size or split by year at roll time.

## Security

- `miner/scan.py:209-227` + `miner/feedback.py:203-247` + `cli/memory.py:96-128` — **transcript-mined "human directives" have no proof of human origin, so repo-controlled text becomes a per-turn instruction.** `_human_prompt_text` accepts any `type:"user"` / `userType:"external"` row whose content is a string or all-`text` blocks; the `origin.kind == "human"` check is `if origin is not None:` — and **the field is absent on this Claude Code version**, so it never fires. Verified against the live store: **220 rows that are slash-command expansions** (`<command-name>…<command-message>…`, keys = `cwd, entrypoint, gitBranch, isSidechain, message, parentUuid, promptId, sessionId, timestamp, type, userType, uuid, version` — no `origin`) pass the filter as "human prompts", as does a row that is a whole injected charter file (`# Instructions (read first)…`). Attack: a repo ships `.claude/commands/<x>.md` (or any prompt-file body expanded into the user turn) containing the plain sentence `Use the <attacker-slug> skill.` — matched by `_POSITIVE_PATTERNS[0]` (`corrections.py:35-41`), and *not* stripped by `_without_quoted_examples`, which only removes backticked/quoted text. Two invocations (distinct `uuid`s ⇒ distinct `event_key`s, same session is enough — `DEFAULT_MIN_SKILL_CORRECTIONS = 2` counts corrections, not sessions) reach `write_skill_feedback`, and from then on **every** `UserPromptSubmit` injects `- \`<attacker-slug>\`: If this skill is currently exposed and its trigger matches or the user names it, invoke and follow it on this turn.` under a header that explicitly tells the model these are *instructions* (`feedback.py:25-28`). Pair it with a planted `.claude/skills/<attacker-slug>/SKILL.md` and repo content has bought itself a standing per-turn invocation directive. — Mitigation, partial and load-bearing: `_valid_slug` (`feedback.py:45-53`) + fixed sentence templates (`feedback.py:25-37,239-247`) cap the payload at a 64-char `[a-z0-9-]` slug inside text dummyindex wrote, so no free-form attacker prose reaches the prompt; `MAX_PROMPT_SKILLS`/`MAX_PROMPT_CHARS` bound volume. Mitigation absent for everything else: `cwd` matching (`scan.py:193-206`) is satisfied by construction (the malicious content *is* this repo's), the mine hook is `>/dev/null 2>&1` and prompt-context sets `suppressOutput: true` (`hooks.py:110-145,147-198`) so neither the write nor the injection is user-visible, and per `plan.md:255-259` **nothing ages it out** — deleting the malicious file does not revoke the promotion, because re-derivation re-reads the historical transcripts forever. Fix: require a positive human marker rather than tolerating an absent one (treat missing `origin` as non-human, or reject rows whose text contains `<command-name>`/`<command-message>`/`<system-reminder>`), and add a max-age window to `aggregate_skill_corrections`.

- `miner/signatures.py:86-99` + `miner/scope.py:52-71` + `miner/render.py:73-87` — **the failure-pattern renderer writes tool *inputs* verbatim into a git-tracked file, and the sanitizer only redacts paths.** `canonical_signature` keeps every non-pagination structured field "byte-for-byte" (`signatures.py:93-99`) and the bash branch keeps the whole command string (lowercased, integers collapsed). `sanitize_signature` rewrites/redacts only things matching `_ABSOLUTE_PATH_RE` — it has no notion of a token, key, or header. So two `Write` calls with the same `content` (a `.env`, a key file) or a repeated `curl -H "authorization: bearer sk-…"` in one session lands the secret inside `.context/session-memory/failure-patterns.md`, which is committed. The rendered banner's own claim, "no excerpt of tool output is kept" (`render.py:60-65`), is true and beside the point: the leak is on the input side. `plan.md:179-186` ("Privacy is structural, not a filter"; "No raw prompt text survives parsing") overclaims — it is accurate for `ToolCallRecord`/`SkillDirectiveEvent`, not for `RepeatedSignature.signature`. — Load-bearing mitigation: only that the pipeline is **unwired** — `write_report` is reachable only from `mine_and_feed`/`scan_transcript_store`, which no CLI verb calls (`cli/memory.py:87-94` routes `mine` to `refresh_skill_feedback`). That is exactly the open question at `plan.md:242-248`: "gets a verb" must not be chosen before this is fixed. Fix: redact-or-hash the signature body for non-allowlisted tools (or render `sha256(signature)[:12]` plus tool name), and correct decision 4's scope claim.

- `cli/memory.py:45-56` + `cli/reconcile_gate.py:24-33` + `context/reconcile_gate.py:240-263,283-295` — **hook-stdin is trusted verbatim by the shared adapter, and the Stop-gate's block-once memo is keyed on a caller-supplied `session_id`, so one ordinary CLI invocation disarms the staleness gate.** `resolve_transcript` turns `hook["transcript_path"]` straight into `Path(tp)` with no containment check against the resolved store (`transcript.py:57-60`), and `session_id` is taken as given. Attack path, no privilege needed and no hook involved — the agent (or anything running as the user) runs one Bash call: `printf '{"session_id":"'"$CLAUDE_CODE_SESSION_ID"'","transcript_path":"/nonexistent"}' | dummyindex context reconcile-gate --root <repo>`. With any index stale, `decide_block` takes the "transcript unreadable but session id present" branch, calls `mark_blocked`, prints an advisory, exits 0 — and the genuine Stop hook then returns `None` at `already_blocked` (`reconcile_gate.py:240-247`). The reconcile gate is silently spent for the session, which is precisely when it was supposed to fire. The same adapter is shared by `guard_doc_write.py:27`, so the trust assumption is repo-wide, and `read_hook_stdin` reads stdin unbounded (`cli/memory.py:34-36`) with no size cap. — Mitigation: **none.** There is no authenticity check on hook stdin, no containment of `transcript_path` under `<config>/projects/`, and no cross-check of the supplied `session_id` against `CLAUDE_CODE_SESSION_ID`. Cheapest fix: in `resolve_transcript`, reject a `transcript_path` that does not resolve under the resolved projects store, and in `decide_block`, only honour an explicit `session_id` that matches the live env id (fall back to `resolve_session_id()` otherwise).

- Checked and clean, recorded so they are not re-litigated: `tool_result` rows are `userType:"external"` but are rejected by the block-type check (`scan.py:238-246`); `.context/cache/` is genuinely gitignored (`.gitignore:19`), so `skill-feedback.json` is not committed; `read_skill_feedback` (`feedback.py:136-200`) does refuse symlinks/non-regular/oversize/duplicate/mis-sorted files fail-closed; running the real grammar over the entire local transcript store produced **one** match (an authentic human prompt), so the false-positive rate on organic content is not the problem — adversarial content is.

## Product surface

- Every prompt in an equipped repo — UserPromptSubmit runs `dummyindex context memory prompt-context` as its own process (`hooks.py:132-143`); measured on this repo at 0.94 s / 1.07 s wall, against a 1.20 s floor for `dummyindex context memory` with no verb (an exit-2 path that opens no store) — gap: the ~1 s is interpreter/import startup paid on every single turn, including turns where `.context/cache/skill-feedback.json` is absent and nothing is printed; no `stat`-first fast path exists before the Python cost.
- Session start in this repo — four dummyindex commands run in the SessionStart array (`hooks.py:147-198`); measured `plan-update` 3.14 s, `memory session-start` 1.14 s, `gc signal` 1.56 s, `memory mine` 1.30 s / 1.52 s ≈ 7.1 s total — gap: `memory mine` contributes ~1.4 s unconditionally; nothing compares transcript-dir mtimes against the last cache write to skip a scan that cannot have changed.
- The wired miner on its own home repo — 19 root-level transcripts / 23 MB under `~/.claude/projects/-mnt-windows-ssd-Projects-dummyindex`, 524 candidate `"type":"user"` rows containing `skill`; `parse_skill_directive_events` across all 19 yields **1** event, below `DEFAULT_MIN_SKILL_CORRECTIONS = 2` (`miner/enums.py:38-40`), so `refresh_skill_feedback` returns `()` and `write_skill_feedback` returns early without creating the cache (`feedback.py:119-120`) — gap: in the repo whose own `.claude/CLAUDE.md` carries a standing `caveman`/`i-have-adhd` instruction, the feature produces zero delivered output while charging the per-session and per-prompt latency above. Precision-first is decision 6; the observable result is that the intended trigger case does not fire.
- A user asking "is skill feedback working?" — `mine` swallows every exception (`cli/memory.py:92-93`) with stdout to `/dev/null` (`hooks.py:185-196`), `prompt-context` sets `suppressOutput: true` (`cli/memory.py:121`), `dummyindex context status` prints only `session-memory: present|absent` (`cli/status.py:57,326`), and `MemoryVerb` has no show/explain/clear member (`memory/enums.py:17-26`) — gap: a broken install, an empty scan, and a working silent run are indistinguishable from the user's seat; there is no way to see what was injected into the last prompt.
- A user who wants the injection off — the reconcile gate names its own opt-out inside the block text (`"auto_council": false`, `reconcile_gate.py:128-130`) and `.remember/` stands emit/nudge/breadcrumb down (`detect.py:8-15`) — gap: neither switch reaches `mine` or `prompt-context` (plan decision 13 states this deliberately); the only off-ramps are editing the managed `.claude/settings.json` hook block or deleting a cache that the next SessionStart rewrites.
- A correction given twice inside one session — the cache refreshes only at SessionStart, and only a directive in the *current* prompt is exempt from the threshold (`feedback.py:227-236`) — gap: the second event of a session does not become durable policy until the next session; the "already said twice" contract holds across sessions, not within one.
- A user types `normal mode` mid-session — that turn's render drops the cached `i-have-adhd` line (`feedback.py:210-225`) — gap: the drop is per-turn only; the cache is untouched until the next `mine`, so the line returns on the following prompt of the same session unless the revocation phrase is retyped.
- Same repo opened through a git worktree, a symlink, or a different mount point — `project_dir_name` dashes the *resolved* absolute path and the store directory must match exactly (`scope.py:41-49`) — gap: corrections given from any alternate path are silently invisible to the primary checkout, with no diagnostic distinguishing "no corrections" from "wrong project dir".
- Multi-profile hosts — `resolve_claude_config_dirs` unions `~/.claude`, `$CLAUDE_CONFIG_DIR`, and every `~/.claude-*` directory (`resolve.py:47-56`); this machine resolves two (`/home/ahmed/.claude`, `/home/ahmed/.claude-os`) — gap: an abandoned or experimental profile keeps promoting skills, the cache records slug+counts only so the contributing profile is not recoverable, and there is no per-profile exclusion.
- A correction from months ago — `aggregate_skill_corrections` counts every post-revocation event in every retained transcript with no time window (`corrections.py:269-281`) — gap: a stale instruction stays on every prompt until the user types a revocation phrase or deletes transcripts; no decay, no per-slug reset verb.
- A repo whose `now.md` has grown — `render_session_start` builds handoff header + full `now.md` body + first 1500 chars of `recent.md` + all of `core-memories.md`, then tail-truncates the whole block at 4000 chars (`emit.py:33-61`) — gap: `core-memories.md` is appended last, so the durable tier is the first content dropped; the user sees `…(truncated)` with no signal that core memories were the casualty.
- A user who never invokes `/dummyindex-remember` — `roll` appears on no hook event (`hooks.py:110-243`); its only caller is step 4 of the skill (`skills/memory/SKILL.md:28-30`) — gap: hand-edited stores never roll, so `now.md` accumulates dated sections and consumes the 4000-char emit budget indefinitely.
