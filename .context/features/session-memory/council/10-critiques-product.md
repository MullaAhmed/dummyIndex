## Product surface

- Every prompt in an equipped repo — UserPromptSubmit runs `dummyindex context memory prompt-context` as its own process (`hooks.py:132-143`); measured on this repo at 0.94 s / 1.07 s wall, against a 1.20 s floor for `dummyindex context memory` with no verb (an exit-2 path that opens no store) — gap: the ~1 s is interpreter/import startup paid on every single turn, including turns where `.context/cache/skill-feedback.json` is absent and nothing is printed; no `stat`-first fast path exists before the Python cost.
- Session start in this repo — four dummyindex commands run in the SessionStart array (`hooks.py:147-198`); measured `plan-update` 3.14 s, `memory session-start` 1.14 s, `gc signal` 1.56 s, `memory mine` 1.30 s / 1.52 s ≈ 7.1 s total — gap: `memory mine` contributes ~1.4 s unconditionally; nothing compares transcript-dir mtimes against the last cache write to skip a scan that cannot have changed.
- The wired miner on its own home repo — 19 root-level transcripts / 23 MB under `~/.claude/projects/-mnt-windows-ssd-Projects-dummyindex`, 524 candidate `"type":"user"` rows containing `skill`; `parse_skill_directive_events` across all 19 yields **1** event, below `DEFAULT_MIN_SKILL_CORRECTIONS = 2` (`miner/enums.py:38-40`), so `refresh_skill_feedback` returns `()` and `write_skill_feedback` returns early without creating the cache (`feedback.py:119-120`) — gap: in the repo whose own `.claude/CLAUDE.md` carries a standing `caveman`/`i-have-adhd` instruction, the feature produces zero delivered output while charging the per-session and per-prompt latency above. Precision-first is decision 6; the observable result is that the intended trigger case does not fire.
- A user asking "is skill feedback working?" — `mine` swallows every exception (`cli/memory.py:92-93`) with stdout to `/dev/null` (`hooks.py:185-196`), `prompt-context` sets `suppressOutput: true` (`cli/memory.py:121`), `dummyindex context status` prints only `session-memory: present|absent` (`cli/status.py:57,326`), and `MemoryVerb` has no show/explain/clear member (`memory/enums.py:17-26`) — gap: a broken install, an empty scan, and a working silent run are indistinguishable from the user's seat; there is no way to see what was injected into the last prompt.
- A user who wants the injection off — the reconcile gate names its own opt-out inside the block text (`"auto_council": false`, `reconcile_gate.py:128-130`) and `.remember/` stands emit/nudge/breadcrumb down (`detect.py:8-15`) — gap: neither switch reaches `mine` or `prompt-context` (plan decision 13 states this deliberately); the only off-ramps are editing the managed `.claude/settings.json` hook block or deleting a cache that the next SessionStart rewrites.
- A correction given twice inside one session — the cache refreshes only at SessionStart, and only a directive in the *current* prompt is exempt from the threshold (`feedback.py:227-236`) — gap: the second event of a session does not become durable policy until the next session; the "already said twice" contract holds across sessions, not within one.
- A user types `normal mode` mid-session — that turn's render drops the cached `i-have-adhd` line (`feedback.py:210-225`) — gap: the drop is per-turn only; the cache is untouched until the next `mine`, so the line returns on the following prompt of the same session unless the revocation phrase is retyped.
- Same repo opened through a git worktree, a symlink, or a different mount point — `project_dir_name` dashes the *resolved* absolute path and the store directory must match exactly (`scope.py:41-49`) — gap: corrections given from any alternate path are silently invisible to the primary checkout, with no diagnostic distinguishing "no corrections" from "wrong project dir".
- Multi-profile hosts — `resolve_claude_config_dirs` unions `~/.claude`, `$CLAUDE_CONFIG_DIR`, and every `~/.claude-*` directory (`resolve.py:47-56`); this machine resolves two (`/home/ahmed/.claude`, `/home/ahmed/.claude-os`) — gap: an abandoned or experimental profile keeps promoting skills, the cache records slug+counts only so the contributing profile is not recoverable, and there is no per-profile exclusion.
- A correction from months ago — `aggregate_skill_corrections` counts every post-revocation event in every retained transcript with no time window (`corrections.py:269-281`) — gap: a stale instruction stays on every prompt until the user types a revocation phrase or deletes transcripts; no decay, no per-slug reset verb.
- A repo whose `now.md` has grown — `render_session_start` builds handoff header + full `now.md` body + first 1500 chars of `recent.md` + all of `core-memories.md`, then tail-truncates the whole block at 4000 chars (`emit.py:33-61`) — gap: `core-memories.md` is appended last, so the durable tier is the first content dropped; the user sees `…(truncated)` with no signal that core memories were the casualty.
- A user who never invokes `/dummyindex-remember` — `roll` appears on no hook event (`hooks.py:110-243`); its only caller is step 4 of the skill (`skills/memory/SKILL.md:28-30`) — gap: hand-edited stores never roll, so `now.md` accumulates dated sections and consumes the 4000-char emit budget indefinitely.
- PreCompact fires after a real handoff was already saved today — `write_breadcrumb` makes the `(auto-breadcrumb)` entry the top section, and `real_handoff_saved_today` inspects only `sections[0]` (`nudge.py:70-79`) — gap: compaction re-arms the Stop nudge for a session that already saved, so the agent offers a handoff the user just made (bounded to once per session by the memo at `nudge.py:56-67`).
- Long-lived store — every roll that moves a section to archive re-renders `archive.md` whole (`roll.py:94-98`); archive is terminal, committed, never emitted by `render_session_start`, never pruned — gap: the only monotonically growing tier is also the only one no surface reads; no cap, prune, or reader verb.
- Reader of `docs/COMMANDS.md:224` and `docs/guide/07-cli.md:484` — both state the `failure-patterns.md` tool-signature miner "remains an explicit command path" / "remains explicit and unwired", but `MemoryVerb` has seven members and none reach `mine_and_feed`; `memory mine` routes to `refresh_skill_feedback` (`cli/memory.py:87-94`) — gap (code wins): the user-facing docs promise a command that does not exist; the only non-test caller of that pipeline is `tests/context/domains/memory/miner/`.
- If the failure-pattern pipeline were given a verb — `write_report` targets `.context/session-memory/failure-patterns.md` (`miner/render.py:11-19,83`), a **committed** directory, not gitignored `cache/`, and `ensure_memory_store`/`roll_tiers`/`render_session_start` all iterate `MemoryTier`, which excludes the filename — gap: its output would be a committed file that no surface reads and no lifecycle maintains; `_ERROR_MARKERS` false-positive rate (`miner/scan.py:29-41`) is unmeasured precisely because nothing consumes it.
- `dummyindex context memory init` in a built repo — `build/runner.py:245-249` calls `ensure_memory_store` on every rebuild, so the store and its four stubs already exist — gap: `init` is documented as a user command (`docs/COMMANDS.md:210`) but is unreachable-by-need for anyone who ran a build; its only distinct output is `memory init: store already present at …`.
- A session that edited source against a stale index — the Stop gate blocks once with a reason that names the drifted features, the exact reconcile/stamp/commit commands, a "don't redo the work" clause, and its own opt-out (`reconcile_gate.py:96-131`), and an unreadable transcript downgrades to an advisory block rather than a hard allow (`reconcile_gate.py:196-220`) — no gap.
- Empty store or missing store — `memory roll` prints `memory roll: no .context/session-memory/ store; nothing to do.` (`cli/memory.py:171-173`) and `session-start` emits nothing when all three tiers are empty (`emit.py:43-44`) — no gap.
