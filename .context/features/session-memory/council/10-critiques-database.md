## Data integrity

- `memory/roll.py:84-98` (`roll_tiers`) — the cascade is three separate `write_text_atomic` calls, and the delete side runs first: `now.md` loses `now_down` at `:84-88` before `recent.md` gains it at `:89-93`, and `recent.md` loses `rec_down` before `archive.md` gains it at `:94-98`. Any failure between them permanently drops the relocated, agent-authored sections. A crash can cause this, but so can an ordinary Windows replace failure: `_replace_bytes` itself notes that readers deny replacement (`atomic_io.py:60-61`), gives up after 6 tries (~150 ms of sleeps, `:55-64`), and unlinks the complete tmp (`:65-67`). `cli/memory.py:174` has no handler. — Write archive → recent → now, so that an interruption duplicates rather than deletes, and make the re-run skip sections already present in the destination tier (exact `Section` equality).
- `memory/breadcrumb.py:49-50` (`write_breadcrumb`) — a new breadcrumb replaces any top `(auto-breadcrumb)` section, with no check of date or session. `roll` runs on no hook (`hooks.py` `_STOP_HOOK`/`_PRE_COMPACT_HOOK`, ~`:155-198`); its only caller is the agent at `skills/memory/SKILL.md:28-30`. So each PreCompact overwrites the previous day's or another session's breadcrumb, and at most one auto-entry survives above the last real handoff. This repo's working `now.md` shows exactly that: one `## 2026-11-08 00:54 | main (auto-breadcrumb)` above a `## 2026-06-22` handoff, with `recent.md` at 10 bytes, i.e. 139 days without a roll. — Replace only when `section_date(sections[0].heading) == now.date()` and the session matches (put the session id in the entry); otherwise prepend.
- `memory/transcript.py:88-161` (`read_session_signal`, `_subagent_edit_count`) — the live-session reader is neither safe on a partial file nor bounded:
  - Partial files: it opens the main and every `subagents/agent-*.jsonl` in strict UTF-8 and catches only `OSError` (`:103,118,131,153`). A tail that ends mid multi-byte character raises `UnicodeDecodeError`, a `ValueError` (verified in scratch), from the `for raw in fh` loop. All three callers then lose that hook's write or decision: the gate (`reconcile_gate.py:352`) fails open, the nudge is dropped, and the breadcrumb is not written. Background subagents append to exactly these files while the parent's Stop fires.
  - Unbounded: every line goes through `json.loads` with no prefilter, and the nothing-owned branch skips `mark_blocked` (`reconcile_gate.py:372-377`). Decision 13 makes subagent-only sessions always nothing-owned, so the gate re-parses everything on every Stop. Here that is 100 subagent files / 122.3 MB, including one session with 61 files / 90.9 MB, so the session costs O(n²).
  - The same strict read in `parse.read_text_or_empty` (`parse.py:16-18`) makes a committed tier saved as non-UTF-8 raise through emit, nudge, breadcrumb and roll.
  - — Open transcripts with `errors="replace"` and reuse the `"type":` substring prefilter from `miner/scan.py:105-113`. Memoize the advisory outcome, or cache the signal keyed on `(path, st_size, st_mtime_ns)`. For tier files, catch and abort instead of `replace`, so U+FFFD is never written back into user text.
- `memory/breadcrumb.py:46-54`, `memory/roll.py:64-98`, `memory/nudge.py:60-67`, `reconcile_gate.py:230-244`, `domains/drift_acks.py:74-76` — every mutation of the store and its caches is an unlocked read-modify-write. `atomic_io.py:40-41` records that two profiles' hooks write one repo concurrently, but a unique tmp prevents only torn files, not lost updates. Effects:
  - a breadcrumb landing between another session's roll read (`roll.py:64`) and its write (`:84`) is erased;
  - a lost memo re-fires a nudge or block, which breaks plan decision 10's "side effects fire once";
  - `ensure_memory_store`'s `exists()` → replace (`store.py:27-29`) can stub over a racing writer's fresh `now.md`, so "non-destructive" holds only for a single writer.
  - — Guard each read-modify-write with the `O_EXCL` lock and stale-steal in `domains/fleetrun.py:_acquire_lock` (`:497-519`), and create stubs with `open(path, "x")`.
- `miner/pipeline.py:100-140` + `miner/corrections.py:251-293` + `miner/feedback.py:110-133` — the skill-feedback cache can drift away from the truth with no detectable signal:
  - It is a pure projection over whatever transcripts the host still retains (this machine: 3 root JSONLs / 16.6 MB). Once host retention (`cleanupPeriodDays`) prunes one of the two qualifying sessions, the count drops below `DEFAULT_MIN_SKILL_CORRECTIONS` and the promotion silently disappears. Plan Open questions ("Nothing ages skill feedback out", `plan.md:284-285`) is therefore wrong in effect: the cache does age out, on the host's clock, invisibly.
  - The writer cannot self-heal. The comparison `read_text` (`feedback.py:128`) has no `st_size` guard (compare the reader's `:142-148`), and on a non-UTF-8 cache it raises `UnicodeDecodeError`, which `except OSError` (`:131`) does not catch. The bare `except` at `cli/memory.py:92-93` swallows it, so the file is never rewritten while the reader returns `()` forever. `refresh_skill_feedback` also discards the write bool (`pipeline.py:139`).
  - — Persist per-slug first/last-seen counts and the latest revocation in the cache (schema 2) and apply the threshold to those. Compare `read_bytes()` after the size guard, and return the write status.
- `memory/parse.py:21,36,52-55,58-70` + `memory/roll.py:39-41,68-78` — the tier codec does not handle every input:
  - `_DATE_RE` accepts non-constructible dates, and `_ordinal` raises `ValueError` at `:41` inside the partition at `:78`, before any write. This is triggered by any bad date in `recent.md` (every recent section is tested) or a lexically-earlier one in `now.md`, e.g. `2026-02-30` or a `PROJ-2024-12-34` token. Every later roll then tracebacks until the heading is hand-fixed. Correction to the last review: such a section never "moves down first". `evolve._harvest_memory` already treats the same case as undated (`evolve.py:354-359`).
  - `split_sections` breaks on any `## ` line, even inside a fence (`:36`), so a roll can send two halves of one entry to different tiers.
  - The round-trip strips bodies and collapses blank runs (`:40,48,70`), so a roll that moves anything reformats and re-sorts every surviving entry. This is the codec's own normalization, not a breach of `write_text_atomic`'s byte-faithful contract (`atomic_io.py:73-77`), and spec.md does not state it.
  - — Make `section_date` return `None` unless `date.fromisoformat` succeeds (with `\b` anchors), track fence state, and either preserve inter-section whitespace or document the normalization.
- `memory/nudge.py:38-46,62-66` + `reconcile_gate.py:209-217,237-243` — the two memo caches check only that the top level is a `dict` and carry no `schema_version`, unlike skill-feedback (`schema_version`), doc-basis (`basis_version`) and drift-acks (`schema_version`). After 100 sessions every mark takes the prune branch. There, one non-dict value raises `AttributeError` at `kv[1].get(...)`, or a non-str timestamp raises `TypeError`, before the write. Every later mark then raises the same way. The shell guard (`|| true; exit 0`) keeps the turn alive, and neither CLI catches in-process (`cli/memory.py:130-142`, `cli/reconcile_gate.py:16-36`). The result is that new sessions are never nudged and the gate permanently fails open. Version skew is real here: this checkout is driven from Windows (`D:\Projects\dummyindex`) and from `/mnt/windows-ssd/Projects/dummyindex` (`concerns.md:31-32`). — Drop non-conforming entries on load, using the fail-closed shape `feedback.py:136-200` already applies, and add `schema_version: 1` to both memos.
- `domains/atomic_io.py:37-67` (`_replace_bytes`) — the only write primitive for the committed tiers has two gaps:
  - Durability is left to the filesystem: there is no `os.fsync(handle.fileno())` before `replace` (`:54-57`) and no directory fsync after it, so a power loss in the writeback window after a PreCompact breadcrumb or a roll can surface an empty `now.md`.
  - `NamedTemporaryFile` (mkstemp) creates the tmp at `0600` and never copies the original mode, so every rewritten tier or cache loses group/other read. Git cannot see this because it tracks only the exec bit.
  - `output/bootstrap.py:489-503` (`_open_atomic_temp`) already calls mkstemp's 0600 "surprising" and fixes it locally.
  - — Allocate the tmp the same way (`O_EXCL`, `0o666` filtered through umask, or copy `st_mode`), and fsync before `replace`.
