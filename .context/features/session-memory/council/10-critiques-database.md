## Data integrity

- `memory/breadcrumb.py:49-52` — the "newest section is already a breadcrumb → replace it" branch checks only `AUTO_BREADCRUMB_TAG`, never the date or session, and `roll_tiers` is wired to **no hook** (only `dummyindex/skills/memory/SKILL.md:30`, i.e. the agent running `/dummyindex-remember`), so for the exact user who relies on breadcrumbs — the one who never saves a handoff — every PreCompact silently destroys the previous day's and every concurrent session's breadcrumb, leaving exactly one auto-entry ever — compare `section_date(sections[0].heading)` against `now.date()` (and the session id) and prepend rather than replace when they differ.
- `memory/roll.py:84-98` — the tier cascade is three independent `write_text_atomic` calls with the *delete* side ordered first (`now.md` minus `now_down` at `84-88`, then `recent.md` plus `now_down` at `89-93`), so any crash, OSError, or SIGKILL between them permanently loses the relocated sections with no tmp file left to recover from — invert to archive → recent → now so an interruption duplicates instead of deletes, and make the re-run drop already-present sections.
- `memory/roll.py:39-41,74` + `memory/parse.py:21,52-55` — `_DATE_RE` accepts any `\d{4}-\d{2}-\d{2}` including non-constructible dates, so a heading containing `2026-13-45` (or a ticket/version token of that shape) makes `_ordinal` raise `ValueError` out of `roll_tiers` into `cli/memory.py:174`, which has no try/except; worse, `_is_before_today` compares strings so the bad section first *moves down* into `recent.md` and then breaks every subsequent roll — have `section_date` return `None` when `date(...)` cannot be constructed, so malformed text is treated as undated.
- `memory/emit.py:40-60` — `now` is inlined in full while `recent` is capped at `_RECENT_HEAD`, and the `max_chars` cut at `59-60` truncates from the end, so once `now.md` passes ~3.9 KB the SessionStart block silently drops `core-memories.md` — the one tier that is never rolled and is meant to be durable — apply `_head` to `now` as well and reserve a fixed budget for `core` before truncating.
- `memory/breadcrumb.py:47-54`, `memory/nudge.py:60-67`, `memory/roll.py:64-98` — every store mutation is an unlocked read-modify-write, while `domains/atomic_io.py:14-18` explicitly documents that two Claude profiles hit the same repo concurrently; `write_text_atomic` prevents a *torn* file but not a *lost update*, so a breadcrumb written between another session's roll-read and roll-write vanishes — guard read-modify-write on the tier store with an `O_EXCL` lock file (the pattern already exists at `context/output/bootstrap.py:499`).
- `domains/atomic_io.py:22-31` — no `flush`/`os.fsync` on the handle before `replace` and no parent-directory fsync, and the tmp sibling is unlinked in `finally`, so a power loss mid-write can leave a zero-length `now.md` with nothing to recover from; this is the git-committed, user-owned half of the store, and the repo lives on a mounted Windows filesystem where rename-after-content ordering is weaker than ext4's — fsync the handle before close and the directory after `replace`.
- `domains/atomic_io.py:22-29` — `NamedTemporaryFile` creates the replacement at `0600` and no mode is copied from the original, so every `.context/session-memory/*.md` and cache file silently loses group/other read permission on its first rewrite (invisible in git, which tracks only the exec bit) — `os.chmod` the tmp to the pre-existing file's `st_mode`, falling back to `0o666 & ~umask` for a new file.
- `miner/pipeline.py:146-152` + `miner/feedback.py:112-133` — `refresh_skill_feedback` discards the `bool` from `write_skill_feedback`, which returns `False` on *every* `OSError` (`117`, `131-132`), and `cli/memory.py:87-94` swallows whatever escapes, so an unwritable `.context/cache/` makes `memory mine` a permanent silent no-op that still returns a populated tuple to its caller — propagate the write outcome and surface it on the non-hook invocation path.
- `miner/feedback.py:113-128` — the write path `lstat`s for symlink/regular but, unlike `read_skill_feedback:143-152`, never checks `st_size` before the `path.read_text()` comparison, so a corrupt or oversize `skill-feedback.json` is decoded into memory in full on every SessionStart — apply the same `MAX_CACHE_BYTES` guard before the comparison read.
- `miner/pipeline.py:112-137` + `miner/corrections.py:269-283` — the cache is a pure projection recomputed from whatever transcripts still exist, with no decay and no durable record, so when the host prunes old JSONL the count falls back below `DEFAULT_MIN_SKILL_CORRECTIONS` (`miner/enums.py:38-40`) and an established skill preference silently disappears; the derived state is non-monotonic in a way no consumer can detect — persist first-seen/last-seen counters in the cache and threshold on those instead of on live transcript availability.
- `memory/parse.py:35-42` — `split_sections` treats any line beginning with `## ` as a boundary with no fenced-code awareness, so a handoff containing a markdown example splits into two sections that `roll_tiers` can then send to *different* tiers, severing a fence and orphaning half an entry — track ` ``` `/`~~~` fence state while scanning.
- `memory/parse.py:40,48,70` — the split/render round-trip is lossy (bodies get `.strip("\n")`, sections are re-joined with exactly one blank line), so a roll silently rewrites the formatting of user-authored entries it did not move, contradicting the byte-faithful contract `write_text_atomic` promises at `domains/atomic_io.py:41-45` — preserve each section's original inter-section whitespace, or state the normalization as the store's contract.
- `memory/nudge.py:38-46,60-67` — `_load_state` validates only that the top level is a `dict`, then `mark_nudged` calls `kv[1].get(...)` on every value, so one non-dict entry raises `AttributeError` through the NUDGE verb, which — unlike MINE and PROMPT_CONTEXT — has no try/except (`cli/memory.py:130-142`), breaking the "a Stop hook must never fail the turn" guarantee asserted on line 142; identical shape at `context/reconcile_gate.py:255-263` — drop non-conforming entries on load, matching the fail-closed validation `miner/feedback.py:136-200` already applies to the sibling cache.
- `memory/roll.py:79,94-98` + `memory/emit.py:40-42` — `archive.md` is append-only with no tier below it and **no reader** (emit consumes now/recent/core only), yet it is git-committed (`.gitignore:19` covers only `.context/cache/`), so it grows without bound in every consumer repo — bound it by size or split by year at roll time.
