## Data integrity

- **Atomicity holds, but through a local clone, not the canonical helper.** `_atomic_write` (`dummyindex/context/output/instructions.py:561-565`) runs `mkdir(parents=True)`, writes `path+".tmp"`, then calls `tmp.replace(path)`. A concurrent reader (statusline badge, drift hook) never sees a half-written doc. The one mandatory rule (`conventions/data-access.md:5-7`) holds. The concern is duplication, not correctness. Nothing is broken today. The code byte-for-byte reimplements `write_text_atomic` (`domains/atomic_io.py:37-47`) instead of calling it. That is the pitfall named in `.context/conventions/data-access.md:27`. Verified equivalent: same `encoding="utf-8"`, no normalization. No data hazard today. Fix path: route the three `write_*` wrappers (`:536`, `:540`, `:557`) through `write_text_atomic`, then delete `_atomic_write`. Low severity.
- **No Windows `PermissionError` fallback.** Unlike the cache writer's copy-then-delete guard (`pipeline/io/cache.py:98-105`), `tmp.replace(path)` (`:565`) can raise on Windows. That happens when a reader holds the target open. For these rarely appended, wholesale-regenerated docs the window is tiny. `build_all` is the sole writer, so impact is low. The shared helper is the natural place to add the guard once.
- **Idempotent, deterministic regeneration confirmed.** Nothing here is non-deterministic. Output depends only on content. The `generate_*` functions return strings and never read disk, the clock or randomness. The static docs are frozen literals (`_HOW_TO_USE` `:23-144`, `_PLAYBOOK_BODIES` `:370-519`). Emission order is stable: `PLAYBOOK_IDS = tuple(sorted(_PLAYBOOK_BODIES))` (`:522`), and `_select_architecture_docs` sorts by `DOC_CONFIDENCE_ORDER` (`:348-364`). Re-running `build_all` over an unchanged index gives byte-identical files. `replace()` makes the swap atomic. No partial-write or duplicate-emission risk.
- **`KeyError` on a miss is the right failure mode.** `generate_playbook_md` rejects an unknown id with a `KeyError` that lists valid ids (`:525-530`). It never emits an empty or placeholder doc. A regeneration over a bad id fails loudly and never writes garbage. Good.

## Security

Adversarial lens: index-derived strings (dir names, file paths, source-doc titles) flow unsanitized into `architecture/overview.md`. Agents read that doc as authoritative navigation. The trust boundary is the repo filesystem and committed `.md` files. The output is not browser-rendered, so the payload is markdown or prompt injection into an agent-facing doc, not XSS. Five threats:

- **HIGH: source-doc title rendered verbatim.** The title is `title = f" — {d.title}"`, interpolated into `f"...(**{d.confidence}**{title})"` (`instructions.py:294-296`). `d.title` comes from the doc H1 (`domains/source_docs/catalog.py:145`, `domains/source_docs/models.py:19`). A `docs/architecture.md` with an instruction-shaped H1 is selected by the `"architecture"` filename signal (`:338-346`). It then sorts to the top of "Documented architecture" (`:363`). Fix: escape or strip control and markdown tokens, collapse to one line, cap length. Latent: `d.confidence` interpolates the bare enum. It renders `high` only because `DocConfidence.__str__` is pinned to `str.__str__` (`enums.py:25-31`). Not a live fault, but fragile.
- **HIGH: markdown-link injection via `d.path`.** `f"- [`{d.path}`](../../{d.path}) ..."` (`:296`) uses `d.path` unescaped as both link text and href. A filesystem-legal `)`, `](` or `../` forges a trusted-looking target or breaks the link. Fix: percent-encode the href, escape the link text, reject `..` and metacharacters.
- **MEDIUM: dir and file names unescaped in table and list.** `` `{s.name}/` `` sits in a 5-column table row (`:262-270`). `` `{f.path}` `` sits in the root list (`:277`). A POSIX-legal backtick, pipe or newline corrupts the table or injects a row. Fix: escape backticks and pipes in cells. Reject newlines.
- **LOW: no bound on catalog or layout size.** `_select_architecture_docs` and the loops emit one line per match with no cap (`:255-300`). Flooding with docs buries the AST ground truth and burns agent context. Fix: cap and elide.
- **NOTE: the atomic write is not a content-trust control. No secrets are emitted.** `_atomic_write` (`:561-565`) only prevents torn reads. The sensitive property is the integrity of agent-facing instructions, which the injection findings cover. The detect-secrets guidance in `HOW_TO_USE` (`:126-136`) is recommended template text. This feature does not enforce it.
