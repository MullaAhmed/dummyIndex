## Data integrity

- `dummyindex/context/domains/docguard/migrate.py:188-228` — `MoveResult` is only constructed *after* the whole loop, so any mid-batch raise (`run_git` → `FileNotFoundError` at `:275` when `.git` exists but the `git` binary does not; `Path.replace` → `OSError`/`IsADirectoryError` at `:272,279,282`; `ensure_audit` → `AuditExistsError` at `:245`, which `cli/migrate_docs.py:83` does **not** catch) leaves N files already relocated and `proposal.json` already written while the operator gets a traceback and **zero record of what moved** — the plan's "no rollback" (`plan.md:61`) is survivable only if there is a forward log, and there isn't — fix: accumulate `moved`/`skipped` into lists emitted from a `try/finally` partial `MoveResult`, and catch `OSError` per item into a `MoveSkip`.

- `dummyindex/context/domains/docguard/migrate.py:193` vs `:197-224` — `_ensure_head` materialises the managed home *before* any move is attempted, so a group whose every move is then skipped (target present at `:197`, or source vanished at `:214`) leaves an orphan `.context/proposals/<slug>/proposal.json` at terminal `status: done` with no `spec.md`/`plan.md`, or a full `ensure_audit` workspace (`audit.json` + `description.md` + `catalog.json` + `findings/`) with no `report.md` — both then read as real records to `proposal list`, `audit show`, and the hygiene GC — fix: materialise the head lazily on the first move that actually executes.

- `dummyindex/context/domains/docguard/migrate.py:180-181` — the dry-run returns before the per-file loop, so a preview's `skipped` carries only the group-level "home already exists" rows and never the per-file clobber skips computed at `:197-213`; `migrate-docs --force --json` therefore advertises moves that the `--yes` run will refuse, and no test pins preview/apply parity (`tests/cli/test_migrate_docs_cli.py:136-150` only pins the key set) — fix: compute target presence in `plan_moves` and record those `MoveSkip`s in the plan, so `apply_moves` re-reports rather than discovers them.

- `dummyindex/context/domains/docguard/classify.py:236-243` + `migrate.py:127-136,197-213` — `_disambiguate` seeds `used` only from slugs minted *in this run* and never from what already exists under `.context/proposals/`, so home identity is a function of the stray set: run 1 migrates `foo-2` and skips `foo` (home pre-exists), run 2 sees the survivor alone, assigns it the bare `foo`, and `--force` fills the **unrelated** existing proposal's missing `spec.md` with this doc's content — clobber-protection (`_is_present`, `:347-354`) only blocks *non-empty* targets, so cross-contamination is silent and reported as a successful move — fix: seed `used` by listing existing `proposals/`/`audits/` slugs, or fold the source directory into the slug so identity is stable across partial runs.

- `dummyindex/context/domains/docguard/migrate.py:280,283` — both `run_git(..., "add", ...)` calls discard `returncode` while the item is unconditionally recorded as `method="replace+add"`, so a concurrent `index.lock`, an ignored destination, or a permissions failure produces a `--json` payload claiming a staged move that was never staged — the file is moved but invisible to git — fix: check `returncode` and downgrade the recorded method to `"replace"` (plus a `MoveSkip` note) when `add` fails.

- `dummyindex/context/domains/docguard/classify.py:135-136` — `group_strays` silently drops planning docs whose stem has no slug-able content, with no `MoveSkip` and no other channel, directly contradicting `cli/migrate_docs.py:27` ("one bad stray is skipped + reported by the domain (a `MoveSkip`), never raised") and its own docstring's "for the caller to surface separately" — nothing surfaces them, so a stray that will *never* migrate is absent from both the human and `--json` output — fix: return the dropped classifications alongside the groups and map them to `MoveSkip`s in `plan_moves`.

- `dummyindex/context/domains/docguard/classify.py:151-152` — a bucket keeps at most one SPEC and one PLAN member via `next(...)`; any additional member is discarded with no `MoveSkip`, and this is reachable on a case-sensitive filesystem because `migrate.py:84` matches the extension case-insensitively (`foo.md` and `foo.MD` bucket together as two PLAN members, same `(directory, pairing_stem)` key) — one real file silently stays in `docs/` and is reported nowhere — fix: detect a >1-member role collision in the bucket and emit a skip instead of taking the first.

- `dummyindex/cli/guard_doc_write.py:75` — `fnmatch` normcases both operands, so a `doc_guard_allow` glob is case-sensitive on POSIX and case-insensitive on Windows; the same committed `config.json` grants different exemptions on different hosts, which for a shared repo is a config value with no single meaning — fix: use `fnmatch.fnmatchcase` (or `PurePosixPath(rel).match`) so the stored glob is host-invariant, and document the `*`-crosses-`/` semantics that `plan.md:97` flags as unspecified.

- `dummyindex/context/domains/config.py:497-521` vs `:270-276` — the two readers of the same two keys disagree on a *present but mistyped* value: `Config.from_dict` raises `ConfigError("config.doc_guard_enabled must be a boolean")` while `read_doc_guard_settings` silently coerces to the `True` default, so a repo that wrote `"doc_guard_enabled": "false"` gets every other config-reading command erroring **and** the guard still denying — the user's intended off-state is honoured by neither path — fix: share one coercion helper, or have the tolerant reader treat a present-but-mistyped key as an explicit `False`-safe fallback rather than silently re-enabling.

- `dummyindex/context/domains/config.py:677-681` — `write_config` writes through a fixed `config.json.tmp` sibling, so two concurrent writers interleave into one temp file before `replace`; this feature raises the exposure by making `config.json` a read on **every** `Write` tool call, and `read_doc_guard_settings:519-521` swallows the resulting parse error into `(True, ())` — a corrupted config silently re-enables the guard and drops the entire allowlist instead of surfacing — fix: write through a unique temp name (`tempfile.mkstemp(dir=out_path.parent)`) before `replace`.

- `dummyindex/context/domains/docguard/migrate.py:94-120` — `plan_moves`/`apply_moves` require the unasserted invariant `context_dir == repo_root/".context"`: targets come from `classify._home_for` (which hardcodes `.context/…` relative to the *repo root*) while `_ensure_head` writes through `context_dir`, so a caller passing a divergent pair would split the head and the relocated files across two directories; today only `cli/migrate_docs.py:71-75` upholds it, and the sole enforcement is the incidental containment check at `:120` reporting a misleading "escapes root" — fix: assert the relationship once at the top of `plan_moves` with its own error message.
