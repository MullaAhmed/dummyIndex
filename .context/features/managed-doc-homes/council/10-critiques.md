# Raw critic findings — managed-doc-homes

## Data integrity

- `dummyindex/context/domains/docguard/migrate.py:188-228` — `MoveResult` is only constructed *after* the whole loop, so any mid-batch raise (`run_git` → `FileNotFoundError` at `:275` when `.git` exists but the `git` binary does not; `Path.replace` → `OSError`/`IsADirectoryError` at `:272,279,282`; `ensure_audit` → `AuditExistsError` at `:245`, which `cli/migrate_docs.py:83` does **not** catch) leaves N files already relocated and `proposal.json` already written while the operator gets a traceback and **zero record of what moved** — the plan's "no rollback" (`plan.md:61`) is survivable only if there is a forward log, and there isn't — fix: accumulate `moved`/`skipped` into lists emitted from a `try/finally` partial `MoveResult`, and catch `OSError` per item into a `MoveSkip`.

- `dummyindex/context/domains/docguard/migrate.py:193` vs `:197-224` — `_ensure_head` materialises the managed home *before* any move is attempted, so a group whose every move is then skipped (target present at `:197`, or source vanished at `:214`) leaves an orphan `.context/proposals/<slug>/proposal.json` at terminal `status: done` with no `spec.md`/`plan.md`, or a full `ensure_audit` workspace (`audit.json` + `description.md` + `catalog.json` + `findings/`) with no `report.md` — both then read as real records to `proposal list`, `audit show`, and the hygiene GC — fix: materialise the head lazily on the first move that actually executes.

- `dummyindex/context/domains/docguard/migrate.py:180-181` — the dry-run returns before the per-file loop, so a preview's `skipped` carries only the group-level "home already exists" rows and never the per-file clobber skips computed at `:197-213`; `migrate-docs --force --json` therefore advertises moves that the `--yes` run will refuse, and no test pins preview/apply parity (`tests/cli/test_migrate_docs_cli.py:136-150` only pins the key set) — fix: compute target presence in `plan_moves` and record those `MoveSkip`s in the plan, so `apply_moves` re-reports rather than discovers them.

- `dummyindex/context/domains/docguard/classify.py:236-243` + `migrate.py:127-136,197-213` — `_disambiguate` seeds `used` only from slugs minted *in this run* and never from what already exists under `.context/proposals/`, so home identity is a function of the stray set: run 1 migrates `foo-2` and skips `foo` (home pre-exists), run 2 sees the survivor alone, assigns it the bare `foo`, and `--force` fills the **unrelated** existing proposal's missing `spec.md` with this doc's content — clobber-protection (`_is_present`, `:347-354`) only blocks *non-empty* targets, so cross-contamination is silent and reported as a successful move — fix: seed `used` by listing existing `proposals/`/`audits/` slugs, or fold the source directory into the slug so identity is stable across partial runs.

- `dummyindex/context/domains/docguard/migrate.py:280,283` — both `run_git(..., "add", ...)` calls discard `returncode` while the item is unconditionally recorded as `method="replace+add"`, so a concurrent `index.lock`, an ignored destination, or a permissions failure produces a `--json` payload claiming a staged move that was never staged — the file is moved but invisible to git — fix: check `returncode` and downgrade the recorded method to `"replace"` (plus a `MoveSkip` note) when `add` fails.

- `dummyindex/context/domains/docguard/classify.py:135-136` — `group_strays` silently drops planning docs whose stem has no slug-able content, with no `MoveSkip` and no other channel, directly contradicting `cli/migrate_docs.py:27` ("one bad stray is skipped + reported by the domain (a `MoveSkip`), never raised") and its own docstring's "for the caller to surface separately" — nothing surfaces them, so a stray that will *never* migrate is absent from both the human and `--json` output — fix: return the dropped classifications alongside the groups and map them to `MoveSkip`s in `plan_moves`.

- `dummyindex/context/domains/docguard/classify.py:151-152` — a bucket keeps at most one SPEC and one PLAN member via `next(...)`; any additional member is discarded with no `MoveSkip`, and this is reachable on a case-sensitive filesystem because `migrate.py:84` matches the extension case-insensitively (`foo.md` and `foo.MD` bucket together as two PLAN members, same `(directory, pairing_stem)` key) — one real file silently stays in `docs/` and is reported nowhere — fix: detect a >1-member role collision in the bucket and emit a skip instead of taking the first.

- `dummyindex/cli/guard_doc_write.py:75` — `fnmatch` normcases both operands, so a `doc_guard_allow` glob is case-sensitive on POSIX and case-insensitive on Windows; the same committed `config.json` grants different exemptions on different hosts, which for a shared repo is a config value with no single meaning — fix: use `fnmatch.fnmatchcase` (or `PurePosixPath(rel).match`) so the stored glob is host-invariant, and document the `*`-crosses-`/` semantics that `plan.md:97` flags as unspecified.

- `dummyindex/context/domains/config.py:497-521` vs `:270-276` — the two readers of the same two keys disagree on a *present but mistyped* value: `Config.from_dict` raises `ConfigError("config.doc_guard_enabled must be a boolean")` while `read_doc_guard_settings` silently coerces to the `True` default, so a repo that wrote `"doc_guard_enabled": "false"` gets every other config-reading command erroring **and** the guard still denying — the user's intended off-state is honoured by neither path — fix: share one coercion helper, or have the tolerant reader treat a present-but-mistyped key as an explicit `False`-safe fallback rather than silently re-enabling.

- `dummyindex/context/domains/config.py:677-681` — `write_config` writes through a fixed `config.json.tmp` sibling, so two concurrent writers interleave into one temp file before `replace`; this feature raises the exposure by making `config.json` a read on **every** `Write` tool call, and `read_doc_guard_settings:519-521` swallows the resulting parse error into `(True, ())` — a corrupted config silently re-enables the guard and drops the entire allowlist instead of surfacing — fix: write through a unique temp name (`tempfile.mkstemp(dir=out_path.parent)`) before `replace`.

- `dummyindex/context/domains/docguard/migrate.py:94-120` — `plan_moves`/`apply_moves` require the unasserted invariant `context_dir == repo_root/".context"`: targets come from `classify._home_for` (which hardcodes `.context/…` relative to the *repo root*) while `_ensure_head` writes through `context_dir`, so a caller passing a divergent pair would split the head and the relocated files across two directories; today only `cli/migrate_docs.py:71-75` upholds it, and the sole enforcement is the incidental containment check at `:120` reporting a misleading "escapes root" — fix: assert the relationship once at the top of `plan_moves` with its own error message.

## Security

Threat model note: the guard is a *hygiene* control over a semi-trusted agent, not a containment boundary — anything that removes `dummyindex` from PATH, or the `2>/dev/null || true` + `exit 0` wrapper in `hooks.py:257-262`, already silently disables it. The findings below are cases where the guard silently disagrees with the filesystem, ranked by how invisibly they fail.

- **[1] `cli/guard_doc_write.py:46` + `cli/common.py:31-34` vs `domains/docguard/classify.py:174-185`** — resolution asymmetry: `resolve_context_root` returns `explicit_root.resolve()` (symlinks followed) while `_rel_posix` uses lexical `Path.relative_to` on the raw `file_path` with a comment explicitly forbidding `resolve()`. When the project is reached through a symlink — symlinked git worktree, `/tmp` → `/private/tmp` on macOS, a home-dir or bind-mount alias — `$CLAUDE_PROJECT_DIR` resolves to the real path, the harness sends the aliased path, `relative_to` raises `DocPathError`, and `run`'s catch-all (`:39-42`) converts it to exit 0. **The guard is then off for every write in the repo, with no output and no error.** Verified: identical `Write` payload for `<root>/docs/plans/x.md` emits the deny through the real root and emits *nothing* through a symlink to that same root. Mitigation: **none** — nothing in `tests/cli/test_guard_doc_write_e2e.py` constructs a symlinked root, so the whole-guard-disabled state is untested. Fix: compare `os.path.realpath` of both sides (once, at the boundary in `guard_doc_write._decide`) before falling back to allow; the classifier stays lexical.

- **[2] `domains/docguard/classify.py:88-102`** — the location gate reads `parts[0]` and `set(interior)` off an un-normalized path, so a `..` segment moves a write across the gate in *both* directions. Verified: `<root>/src/../docs/plans/x.md` classifies `is_planning_doc=False` → allowed, while the write physically lands in `docs/plans/`; inversely `<root>/docs/plans/../guide/x.md` classifies as a stray → **denied**, though it lands in `docs/guide`, an `EXCLUDED_DOCS_SUBTREES` path the design says is never a stray. Attack path: an agent steered by injected content in a repo file (a README, an issue body, a vendored doc) writes the traversal form and the leak the feature exists to stop lands anyway. Mitigation: **none in this code** — it depends entirely on an unverified assumption that Claude Code normalizes `tool_input.file_path`; nothing in the guard, the classifier docstring, or the tests states or pins that assumption. Fix: `os.path.normpath` in `_rel_posix` before `relative_to` — still pure/lexical, no I/O, no contract change.

- **[3] `.context/features/managed-doc-homes/spec.md:32` vs `domains/docguard/decision.py:57-63`** — the stated safety invariant, *"a single bad classification can only ever allow, never block (never `exit 2`)"*, is false as written: `permissionDecision: "deny"` **is** a block of that `Write`; `exit 2` is merely a *second* way to block. Finding [2]'s inverse case is a concrete false-positive deny, and `plan.md:99` concedes a deny is unobservable (no `--json`, no counter, no log). So the feature can block legitimate writes, on a rule tuned by a frozenset of four bare directory names (`constants.py:49`), with no field signal that it is happening. Mitigation: **none** — the escape hatch (`doc_guard_allow`) requires the user to first *diagnose* an invisible deny. Fix: reword the invariant to what the code guarantees ("never blocks the session; only ever denies one `Write`, with a named alternative"), and emit the deny to stderr as well as stdout — stderr is already muted in the hook, so it costs nothing at runtime but is capturable when debugging.

- **[4] `domains/docguard/classify.py:81,85` vs `:89,94,98`** — case handling is inconsistent: the suffix (`rel.suffix.lower()`) and root chrome (`rel.stem.lower()`) are case-folded, but every directory comparison is exact. On the case-insensitive filesystems that are default on macOS and Windows, `Docs/specs/x.md` and `docs/Specs/x.md` both resolve to the same real directories the gate is protecting and both classify as **not planning** (verified). `Docs/` capitalized bypasses the gate entirely, including the filename heuristics, since the location gate runs first. Mitigation: **none**. Fix: case-fold the segment comparisons on the same footing as the suffix.

- **[5] `cli/guard_doc_write.py:61-77` + `domains/config.py:497-521`** — the hook is designed to be installed **globally**, but its enable bit and allowlist come from `.context/config.json` inside whatever repo is currently open — untrusted content in a cloned repo. `doc_guard_enabled: false`, or `doc_guard_allow: ["*"]`, turns a user's global protection off for that repo with zero output. Compounding it, matching is `fnmatch(rel_path, glob)` where `*` crosses `/` (plan open question #4): an author writing `docs/superpowers/*` to exempt one published directory actually exempts everything beneath it recursively — the allowlist is silently broader than its authors will expect, which is validation-as-gesture. (Checked and *not* a threat: `fnmatch.translate` emits atomic groups, so a hostile glob does not ReDoS the hot path — a 45-char `*a*a…b` glob against a 60-char path is sub-millisecond.) Mitigation: **partial** — `read_doc_guard_settings` is correctly bounded (two keys, type-checked, never raises, no full `Config`). Fix: document the `*`-crosses-`/` semantics at the config key, and treat "guard disabled by repo config" as a state worth surfacing once per session rather than never.

- **Verified sound, no finding** — the migration half holds up under the attacks I aimed at it: `migrate.py:115-120` validates every group's containment with `resolve()` on both sides *before* pass 2, so a symlinked `.context/proposals/<slug>` escapes into `MigrationContainmentError` and aborts the whole batch; `_moves_for` always yields ≥1 target under the home, so `_ensure_head`'s un-validated write paths (`:234-258`) are transitively contained; a planted symlink at `proposal.json`/`spec.md` cannot be written through, because `atomic_io._replace_bytes:22-31` and `Path.replace` are both tmp-file-plus-rename and neither follows a destination symlink; `run_git` (`git.py:65-74`) passes an argument list with no shell and absolute paths, so the missing `--` terminator is not reachable as option injection; and the guard reads `tool_input.file_path` only — never `content` — so no document body reaches stdout or any log.

## Product surface

- **Global hook install, repo that never adopted dummyindex** — verified: `guard-doc-write --root <repo-with-no-.context>` on `docs/plans/x.md` emits the deny and exits 0. `_SILENT_GATE` (`hooks.py:103`) gates only on the `dummyindex` binary existing, not on `.context/` presence, and `read_doc_guard_settings` reads `<root>/.context/config.json` (`config.py:497-521`) → absent → `(True, ())`. **Gap:** there is nowhere on disk to write `doc_guard_enabled: false` in such a repo, so the only off switch is uninstalling the hook globally. The documented per-repo escape hatch (`spec.md:36`, `docs/guide/07-cli.md`) does not exist for the repos most likely to be surprised.

- **Same repo, user tries the remediation** — verified: `migrate-docs` exits 2 with `error: …/.context not found. Run \`dummyindex ingest\` first.` (`cli/migrate_docs.py:203-209`). **Gap:** the guard is live in a state where the paired cleanup command refuses to run; the two capabilities have different activation thresholds and nothing tells the user that.

- **Every `Write` in every session pays the hook** — measured on this repo: ~1.0 s per call for `tool_name: "Bash"` (which early-returns at `guard_doc_write.py:49-52`), ~1.2 s for a `.py` `Write`, ~1.07 s for the denying `.md` case. The classifier is free; the Python process is not. **Gap:** the shell gate short-circuits only on a missing binary, so every non-markdown `Write` in every repo in every session pays full interpreter startup for a lexical check on a path string. No filename pre-filter in shell, no memoization.

- **Two strays with the same stem in different directories** — verified: the guard tells `docs/plans/api.md` *and* `docs/internal/plans/api.md` to both write `.context/proposals/api/plan.md`. `group_strays` disambiguates via `_disambiguate` (`classify.py:236-243`); `classify_doc_path` — the guard's only entry — has no `used` set. **Gap:** the shared kernel is shared for *classification* but not for *collision handling*, so an agent obeying two consecutive denies silently overwrites the first file. The migration half is protected against exactly this; the live half is not.

- **Agent obeys a deny and writes `.context/proposals/<slug>/plan.md`** — verified: `gc status --json` then lists `{"slug":"obeyed","status":null,"signals":["untracked"]}`, and `gc/delete.py:_liveness_block:173-186` returns `None` for it (no `proposal.json` status, no partial `checklist.md`). **Gap:** the guard's recommended path yields a proposal home with *strictly less* GC in-flight protection than one from `ensure_proposal` (whose unchecked template checklist reads as in-flight). The deny reason (`decision.py:52-56`) names a directory but no command that mints a valid head, and `write_proposal_json` is reachable only from the migration.

- **Published `docs/` content that happens to match the shape** — verified denies for `docs/specs/openapi.md`, `docs/ui/button-design.md`, `docs/blog/2026-01-01-launch.md`, `docs/adr/2024-03-01-choose-db.md`, `docs/plans/README.md`. `EXCLUDED_DOCS_SUBTREES` is `{guide, reference, sources}` only and is tested against `interior[0]` alone (`classify.py:94`). **Gap:** dated filenames (Jekyll/Hugo posts, ADRs) and `*-design.md` (design systems) are ordinary *published* conventions; each costs an allowlist entry, and the deny text never mentions `doc_guard_allow` — the user is told the write is wrong, not how to declare it legitimate.

- **Tuning the allowlist** — matching is `fnmatch(rel_path, glob)` (`guard_doc_write.py:75`), where `*` crosses `/`. `docs/*` — the natural spelling for "top-level docs files" — exempts the entire `docs/` tree recursively; the documented example `docs/specs/**` (`docs/guide/07-cli.md`) works only because `**` degenerates to `.*.*`. **Gap:** a knob whose blast radius is invisible, with no `--explain`/dry-run to show which paths a glob would exempt and no validation of the glob at config-load time.

- **Setting either knob** — `doc_guard_enabled` / `doc_guard_allow` appear in no CLI verb; a grep over `dummyindex/cli/` finds them only in help prose (`help.py:549`). `ContextSubcommand.CONFIG` does not write them. **Gap:** the escape hatch requires hand-editing `.context/config.json` and knowing the key names from help text, in a file the tool otherwise owns and rewrites via `migrate_config_in_place`.

- **A deny happens mid-task** — the guard prints the payload and nothing else: no `--json`, no counter, no `.context/` record (`guard_doc_write.py:79-82`). **Gap:** concurs with `plan.md` open question 5, with the product consequence stated: a false-positive regime is undetectable from inside a session and unfalsifiable afterwards, so `PLANNING_SEGMENTS` can never be tuned from field evidence.

- **`migrate-docs` dry-run over a tree of symlinked / unslug-able strays** — verified in a scratch repo containing exactly two strays (`docs/plans/linked.md` → symlink, `docs/plans/---.md`): output is `context migrate-docs (dry-run): nothing to migrate`, `--json` gives `{"groups": [], "skipped": []}`. `enumerate_strays` filters symlinks before classification (`migrate.py:82-89`) and `group_strays` drops `suggested_slug is None` (`classify.py:135-136`) with no channel out — despite `classify.py:127-129` claiming they are "dropped here for the caller to surface separately". **Gap + doc conflict (code wins):** `.context/playbooks/migrate-stray-docs.md` step 1 states such a stray "is **skipped + reported** — never moved, never raised." It is never reported. A user reviewing the skip list concludes `docs/` is clean when it is not.

- **`--json` consumer counts relocations** — verified: with a non-empty `.context/proposals/api/plan.md` already present, `--yes --force` returns the move inside `groups[].moves` with `method: ""` *and* the same target inside `skipped`. `groups` is plan-derived, `skipped` is result-derived (`cli/migrate_docs.py:100-139`). **Gap:** reading `groups` alone counts a relocation that did not happen; and the `--force` dry-run of the identical command predicts 1 move / 0 skips, because target-present and source-missing skips are only discovered inside `apply_moves` (`migrate.py:197-224`). Preview does not equal outcome for exactly the flag combination the playbook steers users toward.

- **After a successful migration** — `_print_migrate` (`cli/migrate_docs.py:142-181`) reports moves and skips only; nothing scans inbound references and nothing triggers a rebuild/reconcile. Verified in this repo: `.context/architecture/overview.md:22-37` still links 12 relocated paths (`docs/specs/…`, `docs/internal/specs/…`, `docs/superpowers/specs/…`), two of them graded `DocConfidence.HIGH`/`MEDIUM`, and `ls docs/specs docs/internal` → both gone. **Gap:** broadens `plan.md` open question 2 — the un-followed links are not only in generated `.context/` artifacts but in any doc-site nav or cross-doc link, and the command's own output gives the user no hint that a link-fix + `rebuild --changed` pass is now owed.

- **Leak via a tool other than `Write`** — `cat > docs/plans/x.md` through `Bash`, or `touch` followed by `Edit`, produces the same stray with no deny (matcher at `hooks.py:246-248`). **Gap:** the `Write`-only scoping is a deliberate, well-argued blast-radius decision, but `spec.md:3` sells the guard as stopping the leak "recurring"; it stops one route. Framing overshoots the mechanism — worth stating as advisory-nudge rather than enforcement.
