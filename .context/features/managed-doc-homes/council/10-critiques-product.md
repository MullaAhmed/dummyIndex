# Product-surface critique — Managed doc homes

## Product surface

- **Global hook install, repo that never adopted dummyindex** — verified: `guard-doc-write --root <repo-with-no-.context>` on `docs/plans/x.md` emits the deny and exits 0. `_SILENT_GATE` (`hooks.py:103`) gates only on the `dummyindex` binary existing, not on `.context/` presence, and `read_doc_guard_settings` reads `<root>/.context/config.json` (`config.py:497-521`) → absent → `(True, ())`. **Gap:** there is nowhere on disk to write `doc_guard_enabled: false` in such a repo, so the only off switch is uninstalling the hook globally. The documented per-repo escape hatch (`spec.md:36`, `docs/guide/07-cli.md`) does not exist for the repos most likely to be surprised.

- **Same repo, user tries the remediation** — verified: `migrate-docs` exits 2 with `error: …/.context not found. Run \`dummyindex ingest\` first.` (`cli/migrate_docs.py:203-209`). **Gap:** the guard is live in a state where the paired cleanup command refuses to run; the two capabilities have different activation thresholds and nothing tells the user that.

- **Every `Write` in every session pays the hook** — measured on this repo: ~1.0 s per call for `tool_name: "Bash"` (which early-returns at `guard_doc_write.py:49-52`), ~1.2 s for a `.py` `Write`, ~1.07 s for the denying `.md` case. The classifier is free; the Python process is not. **Gap:** the shell gate short-circuits only on a missing binary, so every non-markdown `Write` in every repo in every session pays full interpreter startup for a lexical check on a path string. No filename pre-filter in shell, no memoization.

- **Two strays with the same stem in different directories** — verified: the guard tells `docs/plans/api.md` *and* `docs/internal/plans/api.md` to both write `.context/proposals/api/plan.md`. `group_strays` disambiguates via `_disambiguate` (`classify.py:236-243`); `classify_doc_path` — the guard's only entry — has no `used` set. **Gap:** the shared kernel is shared for *classification* but not for *collision handling*, so an agent obeying two consecutive denies silently overwrites the first file. The migration half is protected against exactly this; the live half is not.

- **Agent obeys a deny and writes `.context/proposals/<slug>/plan.md`** — verified: `gc status --json` then lists `{"slug":"obeyed","status":null,"signals":["untracked"]}`, and `gc/delete.py:_liveness_block:173-186` returns `None` for it (no `proposal.json` status, no partial `checklist.md`). **Gap:** the guard's recommended path yields a proposal home with *strictly less* GC in-flight protection than one from `ensure_proposal` (whose unchecked template checklist reads as in-flight). The deny reason (`decision.py:52-56`) names a directory but no command that mints a valid head, and `write_proposal_json` is reachable only from the migration.

- **Published `docs/` content that happens to match the shape** — verified denies for `docs/specs/openapi.md`, `docs/ui/button-design.md`, `docs/blog/2026-01-01-launch.md`, `docs/adr/2024-03-01-choose-db.md`, `docs/plans/README.md`. `EXCLUDED_DOCS_SUBTREES` is `{guide, reference, sources}` only and is tested against `interior[0]` alone (`classify.py:94`). **Gap:** dated filenames (Jekyll/Hugo posts, ADRs) and `*-design.md` (design systems) are ordinary *published* conventions; each costs an allowlist entry, and the deny text never mentions `doc_guard_allow` — the user is told the write is wrong, not how to declare it legitimate.

- **Tuning the allowlist** — matching is `fnmatch(rel_path, glob)` (`guard_doc_write.py:75`), where `*` crosses `/`. `docs/*` — the natural spelling for "top-level docs files" — exempts the entire `docs/` tree recursively; the documented example `docs/specs/**` (`docs/guide/07-cli.md`) works only because `**` degenerates to `.*.*`. **Gap:** a knob whose blast radius is invisible, with no `--explain`/dry-run to show which paths a glob would exempt and no validation of the glob at config-load time.

- **Setting either knob** — `doc_guard_enabled` / `doc_guard_allow` appear in no CLI verb; a grep over `dummyindex/cli/` finds them only in help prose (`help.py:549`). `ContextSubcommand.CONFIG` does not write them. **Gap:** the escape hatch requires hand-editing `.context/config.json` and knowing the key names from help text, in a file the tool otherwise owns and rewrites via `migrate_config_in_place`.

- **A deny happens mid-task** — the guard prints the payload and nothing else: no `--json`, no counter, no `.context/` record (`guard_doc_write.py:79-82`). **Gap:** concurs with `plan.md` open question 5, with the product consequence stated: a false-positive regime is undetectable from inside a session and unfalsifiable afterwards, so `PLANNING_SEGMENTS` can never be tuned from field evidence.

- **`migrate-docs` dry-run over a tree of symlinked / unslug-able strays** — verified in a scratch repo containing exactly two strays (`docs/plans/linked.md` → symlink, `docs/plans/---.md`): output is `context migrate-docs (dry-run): nothing to migrate`, `--json` gives `{"groups": [], "skipped": []}`. `enumerate_strays` filters symlinks before classification (`migrate.py:82-89`) and `group_strays` drops `suggested_slug is None` (`classify.py:135-136`) with no channel out — despite `classify.py:127-129` claiming they are "dropped here for the caller to surface separately". **Gap + doc conflict (code wins):** `.context/playbooks/migrate-stray-docs.md` step 1 states such a stray "is **skipped + reported** — never moved, never raised." It is never reported. A user reviewing the skip list concludes `docs/` is clean when it is not.

- **`--json` consumer counts relocations** — verified: with a non-empty `.context/proposals/api/plan.md` already present, `--yes --force` returns the move inside `groups[].moves` with `method: ""` *and* the same target inside `skipped`. `groups` is plan-derived, `skipped` is result-derived (`cli/migrate_docs.py:100-139`). **Gap:** reading `groups` alone counts a relocation that did not happen; and the `--force` dry-run of the identical command predicts 1 move / 0 skips, because target-present and source-missing skips are only discovered inside `apply_moves` (`migrate.py:197-224`). Preview does not equal outcome for exactly the flag combination the playbook steers users toward.

- **After a successful migration** — `_print_migrate` (`cli/migrate_docs.py:142-181`) reports moves and skips only; nothing scans inbound references and nothing triggers a rebuild/reconcile. Verified in this repo: `.context/architecture/overview.md:22-37` still links 12 relocated paths (`docs/specs/…`, `docs/internal/specs/…`, `docs/superpowers/specs/…`), two of them graded `DocConfidence.HIGH`/`MEDIUM`, and `ls docs/specs docs/internal` → both gone. **Gap:** broadens `plan.md` open question 2 — the un-followed links are not only in generated `.context/` artifacts but in any doc-site nav or cross-doc link, and the command's own output gives the user no hint that a link-fix + `rebuild --changed` pass is now owed.

- **Leak via a tool other than `Write`** — `cat > docs/plans/x.md` through `Bash`, or `touch` followed by `Edit`, produces the same stray with no deny (matcher at `hooks.py:246-248`). **Gap:** the `Write`-only scoping is a deliberate, well-argued blast-radius decision, but `spec.md:3` sells the guard as stopping the leak "recurring"; it stops one route. Framing overshoots the mechanism — worth stating as advisory-nudge rather than enforcement.
