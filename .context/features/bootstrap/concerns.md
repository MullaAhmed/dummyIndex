## Data integrity

There is no relational database in this feature. Integrity depends on preserving user-authored guidance across filesystem snapshots and atomic replaces.

- **High — consolidation can overwrite and then delete a concurrently edited root file.** `reconcile_claude_md` snapshots existence and both files. It builds a full replacement from those strings, with no lock, inode check, mtime check, or revalidation (`dummyindex/context/output/claude_md.py:126-209`). It then replaces canonical and unlinks root based on that snapshot (`dummyindex/context/output/claude_md.py:221-269`). If root changes after the read, stale bytes reach canonical and the newer root is deleted. A concurrent canonical edit is overwritten too. The historical fixed-name temp collision is closed: `write_text_atomic` allocates a unique `NamedTemporaryFile` sibling (`dummyindex/context/domains/atomic_io.py:15-45`). Snapshot staleness remains. Lock the root and canonical pair for the whole transaction, and revalidate identities and content before `replace` and unlink.

- **High — the inode-shared repair path breaks hardlink identity and leaves a stale second file.** `_same_file` routes root and canonical aliases to `_refresh_single_file` (`dummyindex/context/output/claude_md.py:129-133`, `dummyindex/context/output/claude_md.py:272-279`). On a changed block, that helper calls `write_text_atomic` on the canonical path only (`dummyindex/context/output/claude_md.py:282-336`). Its temp-and-replace creates a new inode for that entry (`dummyindex/context/domains/atomic_io.py:15-45`). With hardlinks, root keeps the stale inode while canonical gets the new one, which contradicts the single-file premise. A canonical symlink can also become a regular file. Preserve alias semantics explicitly, or refuse and warn instead of reporting a shared-file refresh.

- **Medium — legacy consolidation is not byte-preserving for user residue.** `_user_residue` calls `.strip()` after removing managed spans (`dummyindex/context/output/claude_md.py:75-93`). Both reads use universal-newline text mode (`dummyindex/context/output/claude_md.py:135-178`). The merge rebuilds separators with `\n` (`dummyindex/context/output/claude_md.py:190-209`). That drops edge whitespace, normalizes CRLF and mixed endings, and can change indented Markdown code blocks. Preserve exact residue segments and the original newline policy, or validate any normalization before deleting the source.

- **Medium — byte-idempotent direct bootstrap is not filesystem-state idempotent.** Even when assembly reproduces the existing string, `bootstrap_claude_md` always calls `_atomic_write` (`dummyindex/context/output/bootstrap.py:155-205`). That writer replaces the inode and records only `stat.S_IMODE`. A no-change run can therefore sever hardlinks and drop xattrs, ACLs, ownership nuances, and timestamps (`dummyindex/context/output/bootstrap.py:469-488`). Skip the write when `new_content == existing`. When content changes, define and preserve the metadata contract beyond mode bits where the platform supports it.

- **Medium — `--platform both` can commit only one host file despite successful preflight.** The CLI preflights Claude and Codex, writes Claude, then recomputes and writes the Codex target (`dummyindex/cli/bootstrap.py:50-74`, `dummyindex/context/output/agents_md.py:115-167`). A post-preflight race, changed fallback selection, or Codex write failure returns exit 3 after Claude is committed, with no rollback. Either stage both payloads and commit through a recoverable journal. Or return a structured partial-success result naming the file already changed.

- **Medium — direct Claude bootstrap can create the two-location state that reconciliation treats as legacy drift.** The managed marker tells users to regenerate with `dummyindex context bootstrap` (`dummyindex/context/output/bootstrap.py:14-17`). That CLI always writes `<root>/.claude/CLAUDE.md` through the single-file renderer and never inspects `<root>/CLAUDE.md` (`dummyindex/cli/bootstrap.py:36-66`). A legacy root block survives, so the command succeeds beside it. Only a later build, install, or migration through `reconcile_claude_md` restores one canonical file (`dummyindex/context/output/claude_md.py:96-110`, `dummyindex/context/output/claude_md.py:211-269`). Route direct bootstrap through the reconciler, or reject and report a legacy root file before creating a second region.

## Security

- **[RESOLVED] Legacy reconciliation's predictable-temp symlink clobber is closed by the unique-temp helper.** It was `dummyindex/context/output/claude_md.py:112-115,221-224,321-323` plus a fixed `.claude/CLAUDE.md.tmp`. Both consolidation writes now delegate to `write_text_atomic` (`dummyindex/context/output/claude_md.py:223`, `:322`). Its `NamedTemporaryFile` sibling uses a random exclusive name that cannot be pre-created as a symlink (`dummyindex/context/domains/atomic_io.py:15-45`). This matches the direct renderer's unique `O_EXCL` allocator (`dummyindex/context/output/bootstrap.py:501-515`). Residual exposure is the check-then-use issue below, which stays the open hardening item.

- **[HIGH] Resolved-path containment is check-then-use, so a parent-symlink swap can redirect the atomic write after approval** — `dummyindex/context/output/bootstrap.py:121-137,155-205,469-488`, `dummyindex/cli/bootstrap.py:50-66`, and `dummyindex/context/output/agents_md.py:147-167,260-275`. Attack scenario: in a shared workspace, a `.claude` or nested Codex fallback parent resolves inside the project. Preflight passes. A concurrent attacker then repoints that parent symlink outside the project before `_open_atomic_temp`. Temp creation and `replace` then run in the attacker's directory. Mitigation: full-path resolution rejects stable out-of-scope links, and random exclusive temp names block pre-creation. Neither binds the checked directory chain to the write. Open the project and descendant directories through retained dirfds with no-follow or beneath semantics, such as `openat2` where available. Create and rename the temp relative to the verified parent. Otherwise, detect inode changes and fail closed.

- **[MED] Direct bootstrap silently drops access-control metadata, so refresh can broaden read access** — `dummyindex/context/output/bootstrap.py:155-205,469-488` and `dummyindex/context/output/agents_md.py:115-136`. Attack scenario: a shared repository protects `CLAUDE.md` or `AGENTS.md` with a named-user ACL or security xattr. That ACL is stricter than the mode bits. Bootstrap records only `stat.S_IMODE`, creates a new inode, reapplies those bits, and replaces the target. It copies no ACL, xattr, ownership, or security label. A collaborator the ACL denied can then read through permissive group or other bits. This happens even when the bytes already match, because the writer never skips. Mitigation: skip publication when bytes match. For changed files, copy and verify supported ownership, ACL, xattr, and security-label metadata before replacement, or fail closed.

## Product surface

- **A repository still has a legacy root `CLAUDE.md`, and the user follows the marker's `dummyindex context bootstrap` instruction.** The command writes only `<root>/.claude/CLAUDE.md` and never calls the root-to-canonical reconciler. It can report success while the stale block that directed the user stays untouched. The instruction lives in the stable Claude begin marker (`dummyindex/context/output/bootstrap.py:14-17`). The CLI always selects the canonical path and calls the single-file renderer (`dummyindex/cli/bootstrap.py:36-66`). Root folding is separate, used by build, install, and migration (`dummyindex/context/output/claude_md.py:96-110`, `dummyindex/context/output/claude_md.py:211-269`).

- **A user or editor saves legacy root `CLAUDE.md` while install, build, or refresh consolidates it.** Reconciliation commits its earlier snapshot and deletes the newer root. Nothing warns, and the operation still reports successful guidance setup. The reconciler reads both files, skips identity and content revalidation, then writes canonical and unlinks root (`dummyindex/context/output/claude_md.py:126-209`, `dummyindex/context/output/claude_md.py:221-269`). Build marks guidance ready (`dummyindex/context/build/runner.py:297-303`), while install and migration print success (`dummyindex/installer/install/project_init.py:96-101`, `dummyindex/cli/migrate.py:95-110`). The surface needs conflict detection that keeps both copies and names the changed path.

- **A user runs `context bootstrap --platform both`. Both preflights pass, then the Codex target changes or becomes unwritable.** Claude is already committed and announced when exit 3 returns. The single "both" operation leaves host guidance split, with no rollback or partial-success summary. Deterministic conflicts are checked before mutation, but Claude is written first and Codex is recomputed and written after (`dummyindex/cli/bootstrap.py:59-74`, `dummyindex/context/output/agents_md.py:115-167`). The preflight blocks known conflicts, not post-check changes.

- **A user wants to stop using dummyindex's Claude project guidance without hand-editing managed markers.** The renderer has a validated `remove_managed_block`, but `context bootstrap` exposes only create and update. Claude uninstall leaves project guidance intact by design, so there is no public inverse for the Claude block. The remover preserves surrounding content and handles empty files and symlinks (`dummyindex/context/output/bootstrap.py:208-253`). The bootstrap CLI accepts only root and platform (`dummyindex/cli/bootstrap.py:10-86`). Uninstall documents the retained guidance (`dummyindex/installer/args.py:55`). The marker forbids hand edits but gives no removal command.

- **A user reruns direct bootstrap to check that guidance is current.** Identical bytes still go through atomic replacement. The CLI prints the same `managed block written` line used for create and update. The check can silently change filesystem security state. `bootstrap_claude_md` always calls `_atomic_write` after assembly, even when `new_content == existing` (`dummyindex/context/output/bootstrap.py:155-205`). That writer creates a new inode and restores only mode bits. It discards hardlink identity, ACLs, security xattrs, ownership nuances, and timestamps (`dummyindex/context/output/bootstrap.py:469-488`). The string return and the fixed success line do not distinguish create, update, or no-op (`dummyindex/cli/bootstrap.py:59-74`).

- **A cautious user wants to inspect the exact Claude and Codex changes before applying them.** Public bootstrap help offers only path, root, and platform. Every successful command writes, and there is no read-only preview, diff, or check mode. Help is intercepted before side effects, but its surface has no dry-run option (`dummyindex/cli/help.py:54`, `dummyindex/cli/__init__.py:97`). The preflight helpers are internal to the `both` path, not a user-visible preview (`dummyindex/cli/bootstrap.py:26-57`).

- **The installer ships ten skill families, but every guidance block's workflow list predates two of them.** The main family plus nine `_SIBLING_SKILLS` now includes `dummyindex-fleet` and `dummyindex-evolve`. `ALWAYS_ON_SKILL_POLICY` routes planning, building, auditing, equipping, updating, remembering, and garbage collection, without fleet or evolve (`dummyindex/context/output/bootstrap.py:69-81`). Codex's `_PROJECT_BLOCK` lists the same eight-workflow roster ending at `dummyindex-update` (`dummyindex/context/output/agents_md.py:43-46`). A new repo gets no specific routing for evolve or fleet requests. Only the generic trigger-rule clause covers them. The routing text lags the family registry (`dummyindex/installer/common.py:87-97`). Fix: enumerate families from one shared source, or rely on the `dummyindex-*` prefix rule alone.
