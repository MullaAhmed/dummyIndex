# Audit Panel and Onboarding Specification

confidence: INFERRED

## Intent

Provide deterministic Python contracts for two adjacent concerns. Scaffold an adversarial-audit workspace that an agent skill executes. Persist host-aware onboarding choices that audit and council workflows consume. Core logic owns schema validation, legacy migration, default-plugin policy, model and mode resolution, persona roster resolution, and slug safety. CLI, installer, and atomic writes are plumbing around those decisions.

## User-visible behavior

- `dummyindex context onboard` requires an existing `.context/` directory. It validates flags into an immutable schema-v5 `Config`. It writes `.context/config.json` and echoes the stamped bytes. The skill keeps the interactive questions. This CLI is the persistence boundary (`dummyindex/cli/onboard.py:1-35`, `dummyindex/cli/onboard.py:114-191`).
- Non-default onboarding requires `--model`. It accepts repo, subdir, or explicit scope. Modes are `light`, `standard`, or `deep`. Models are the generation-less families `current|opus|sonnet|haiku|fable`. It accepts hook on or off, repeatable external-doc paths, and an optional host set: `claude`, `agents`, or `both`. `codex` is a deprecated alias (`dummyindex/cli/onboard.py:10-24`, `dummyindex/cli/onboard.py:194-218`).
- `--defaults` chooses a host-aware baseline. Claude uses Sonnet, hooks, reviewed default-plugin declarations, and enabled default state. Codex uses the current session, no Claude hook, an empty ledger, and not-applicable `null`. The `both` host uses `current`, hooks, defaults, and enabled state (`dummyindex/context/domains/config.py:498-529`).
- Without `--platform`, defaults infer host coverage only from exact managed Claude and Codex guidance markers. No marker falls back to Claude. Explicit host, model, and hook combinations that cannot be honored return exit 2 without writing (`dummyindex/cli/onboard.py:221-277`, `tests/context/domains/test_config.py:543-806`).
- Schema 4 and up require `default_plugins_enabled` to be `true`, `false`, or `null`. `true` opts a Claude-enabled repo into reviewed defaults. `false` is a durable all-defaults opt-out. `null` records a Codex-only not-applicable baseline (`dummyindex/context/domains/config.py:226-239`, `dummyindex/context/domains/config.py:449-479`).
- Legacy reads normalize to schema 5 in memory. V1 `wire_superpowers` maps directly to enabled or disabled state. V2 and v3 treat a nonempty `wired` ledger as enabled. An empty ledger means disabled, except the exact canonical Codex baseline (`null`). Version-pinned labels, such as `opus-4.8` and `sonnet-4.6`, migrate single-hop through `_LEGACY_MODEL_VALUES` before enum validation (`dummyindex/context/domains/config.py:97-104`, `dummyindex/context/domains/config.py:262-354`, `dummyindex/context/domains/config.py:409-495`, `tests/context/domains/test_config.py:1061-1183`).
- Migration rewrites only loadable stale schemas, renamed model values, or a stale schema whose model alone is legacy. It preserves existing choices. Reconciliation leaves Codex and explicit `false` byte-identical. For Claude or both, it changes `null` to `true`. It appends missing reviewed defaults after custom entries (`dummyindex/context/domains/config.py:599-638`, `dummyindex/context/domains/config.py:696-733`, `tests/context/domains/test_config.py:1185-1295`).
- Audit startup resolves model by flag, then config, and never silently invents one. It resolves mode through one shared depth seam: flag, audit-specific command depth, global mode, then standard (`dummyindex/context/domains/audit/workspace.py:104-140`, `dummyindex/context/domains/config.py:532-551`).
- An audit can scaffold without a pre-existing index. It validates or derives a safe slug. It refuses an existing workspace unless forced. It atomically writes `audit.json`, `description.md`, and `catalog.json`, plus `findings/` (`dummyindex/context/domains/audit/workspace.py:56-101`, `dummyindex/context/domains/audit/workspace.py:143-213`, `tests/context/domains/audit/test_audit_domain.py:216-281`).
- The audit skill owns panel orchestration, synthesis, and closeout. The CLI scaffolds state, not auditors. After finalizing the report, the host may submit one lesson-shaped `learning_reflection`. Its fields are `verified`, `cue`, `lesson`, `evidence`, and `confidence`. It goes through audit GC closeout with `transfers: []`. `body` is ignored. Learning preserves owner text and runs the gate. Only `failed` exits 1. Audited source stays read-only. The report is frozen after the closeout receipt (`dummyindex/skills/audit/SKILL.md`, `dummyindex/context/domains/proposals/closeout.py:150-158`, `dummyindex/context/domains/evolve_learning.py:166`, `dummyindex/context/domains/living_rules.py:75-150`).
- Persona cards come from the shipped markdown catalog. Roster resolution keeps an installed requested agent. Else it selects the first capability match, or `general-purpose`. When no roster source exists, shipped names remain untouched (`dummyindex/context/domains/audit/catalog.py:56-76`, `dummyindex/context/domains/audit/catalog.py:96-196`).

## Contracts

- `Config` is a frozen schema-v5 record. It holds `scope`, `scope_path`, `mode`, `model`, `auto_refresh_hook`, and exclusions. It also holds per-command depths, the declarative `wired` ledger, tri-state `default_plugins_enabled`, writer version, and doc-guard settings. The v5 `build` policy carries `BuildPolicy.auto_recouncil`, default true. Subdir scope requires a nonempty path. Default-plugin state accepts only boolean or null (`dummyindex/context/domains/config.py:206-230`).
- `Config.from_dict(payload: dict[str, Any]) -> Config` strictly accepts schema versions 1 through 5. It rejects bool-as-version and future versions. It validates enums and collection shapes. It performs legacy migrations, including `_LEGACY_MODEL_VALUES` mapping. (`dummyindex/context/domains/config.py:262-354`).
- `default_config(*, platform: str = "claude") -> Config` accepts only `claude`, `codex`, or `both`. It returns the matching host-aware baseline (`dummyindex/context/domains/config.py:498-529`).
- `read_config(context_dir: Path) -> Config | None` returns `None` only when the file is absent. It raises `ConfigError` on malformed or unsupported content. `write_config(context_dir: Path, config: Config) -> Path` stamps the current CLI version. It writes pretty JSON through tmp-and-replace (`dummyindex/context/domains/config.py:554-568`, `dummyindex/context/domains/config.py:736-756`).
- `migrate_config_in_place(context_dir: Path) -> bool` rewrites only a loadable stale schema or legacy model value. It reports whether bytes moved. A legacy model label alone in an otherwise-current config counts as stale (`dummyindex/context/domains/config.py:599-638`).
- `reconcile_default_plugins(context_dir: Path, *, platform: str) -> bool` preserves explicit opt-out. It promotes not-applicable state only for Claude-enabled hosts. It appends missing defaults after existing entries. It avoids no-op writes. It raises on malformed config (`dummyindex/context/domains/config.py:696-733`).
- `resolve_depth(context_dir: Path, command: DepthCommand, depth_flag: str | None) -> CouncilMode` centralizes flag, per-command, global, and standard fallback precedence (`dummyindex/context/domains/config.py:532-551`).
- `onboard.run(args: list[str]) -> int` returns 0 after writing. It returns 2 for invalid arguments or a missing `.context/`. It emits the persisted config after its status line (`dummyindex/cli/onboard.py:114-191`).
- `AuditConfig`, `PersonaCard`, and `AuditStart` are frozen, JSON-shaped records. Audit deserialization requires schema 1 and an explicit model. `PersonaCard` retains the originally requested agent when roster resolution rewrites it (`dummyindex/context/domains/audit/models.py:22-126`).
- `resolve_model(context_dir: Path, model_flag: str | None) -> ModelChoice` uses the flag, then readable config. Otherwise it raises `ModelRequiredError`. `resolve_mode(context_dir: Path, mode_flag: str | None) -> CouncilMode` delegates to the shared audit depth resolver. It translates config errors into audit errors (`dummyindex/context/domains/audit/workspace.py:104-140`).
- `ensure_audit(context_dir: Path, *, description, mode, model, scope=(), slug=None, force=False, personas_dir=None, roster=...) -> AuditStart` creates the deterministic audit workspace and resolved persona menu. It does not select or run the panel (`dummyindex/context/domains/audit/workspace.py:143-213`).
- `load_catalog(personas_dir: Path) -> tuple[PersonaCard, ...]`, `collect_roster(project_root: Path, context_dir: Path) -> tuple[RosterAgent, ...] | None`, and `resolve_catalog(cards, roster) -> tuple[PersonaCard, ...]` form the parse, observe, and resolve pipeline (`dummyindex/context/domains/audit/catalog.py:65-196`).

## Examples

- `dummyindex context onboard --defaults --platform codex` persists `model: "current"`, disables Claude hooks, leaves `wired` empty, and records `default_plugins_enabled: null` (`dummyindex/context/domains/config.py:498-529`, `tests/context/domains/test_config.py:543-573`).
- A v3 canonical Codex baseline with no default-plugin field loads as `null`. The same schema with an explicitly empty non-Codex ledger loads as `false` (`tests/context/domains/test_config.py:1145-1168`).
- Reconciling that Codex baseline for `both` changes the state to `true`. It appends all reviewed defaults at once. Reconciling with `platform="codex"` changes no bytes (`tests/context/domains/test_config.py:1203-1251`).
- Starting an audit for `Audit error handling in the CLI dispatcher` derives `audit-error-handling-in-the-cli-dispatcher`. It writes the three scaffold files and `findings/`. It round-trips its explicit model and scope (`tests/context/domains/audit/test_audit_domain.py:216-249`).
- A shipped security persona resolves to an equipped security-capability agent. It retains `Security Engineer` as `requested_subagent_type`. A bare repo keeps the shipped name, because global agents are unknowable (`tests/context/domains/audit/test_audit_domain.py:519-589`).
