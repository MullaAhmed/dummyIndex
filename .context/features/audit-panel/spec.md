# Audit Panel and Onboarding Specification

confidence: INFERRED

## Intent

Provide deterministic Python contracts for two adjacent concerns: scaffold an adversarial-audit workspace that an agent skill can execute, and persist host-aware onboarding choices that audit and other council workflows consume. Core logic owns schema validation, legacy migration, default-plugin policy, model and mode resolution, persona roster resolution, and slug safety; CLI, installer, and atomic file-writing code are plumbing around those decisions.

## User-visible behavior

- `dummyindex context onboard` requires an existing `.context/` directory, validates flags into an immutable schema-v5 `Config`, writes `.context/config.json`, and echoes the exact stamped bytes written. The interactive question flow remains in the skill; this CLI is its persistence boundary (`dummyindex/cli/onboard.py:1-35`, `dummyindex/cli/onboard.py:114-191`).
- Non-default onboarding requires `--model`. It accepts repo, subdir, or explicit scope; light, standard, or deep mode; the generation-less model families `current|opus|sonnet|haiku|fable`; hook on/off; repeatable external-doc paths; and an optional host set of `claude`, `agents`, or `both` (`codex` is accepted as a deprecated alias normalized to the internal token) (`dummyindex/cli/onboard.py:10-24`, `dummyindex/cli/onboard.py:194-218`).
- `--defaults` chooses a host-aware baseline. Claude uses Sonnet, hooks, reviewed default-plugin declarations, and enabled default state; Codex uses the current session, no Claude hook, an empty ledger, and not-applicable `null`; both uses current, hooks, defaults, and enabled state (`dummyindex/context/domains/config.py:498-529`).
- Without an explicit `--platform`, defaults infer host coverage only from dummyindex's exact managed Claude and Codex guidance markers; no marker falls back to Claude. Explicit host/model/hook combinations that cannot be honored return exit 2 without writing (`dummyindex/cli/onboard.py:221-277`, `tests/context/domains/test_config.py:543-806`).
- Schema 4 and up require `default_plugins_enabled` to be `true`, `false`, or `null`. `true` opts a Claude-enabled repo into reviewed defaults, `false` is a durable all-defaults opt-out, and `null` records a Codex-only not-applicable baseline (`dummyindex/context/domains/config.py:226-239`, `dummyindex/context/domains/config.py:449-479`).
- Legacy reads normalize to schema 5 in memory. V1 `wire_superpowers` maps directly to enabled/disabled state; v2/v3 use a nonempty `wired` ledger as enabled and an empty ledger as disabled, except the exact canonical Codex baseline maps to `null`. Version-pinned model labels (`opus-4.8`, `sonnet-4.6`, …) read-migrate single-hop to their family through `_LEGACY_MODEL_VALUES` before enum validation (`dummyindex/context/domains/config.py:97-104`, `dummyindex/context/domains/config.py:262-354`, `dummyindex/context/domains/config.py:409-495`, `tests/context/domains/test_config.py:1061-1183`).
- Installer migration rewrites only loadable stale schemas, renamed model values, or a stale schema whose model alone is legacy, and preserves existing choices. Default-plugin reconciliation is a byte-identical no-op for Codex and explicit `false`; for Claude or both, it changes `null` to `true` and appends missing reviewed defaults after existing custom entries (`dummyindex/context/domains/config.py:599-638`, `dummyindex/context/domains/config.py:696-733`, `tests/context/domains/test_config.py:1185-1295`).
- Audit startup resolves model by flag then config and never silently invents one; it resolves mode by one shared depth seam: flag, audit-specific command depth, global mode, then standard (`dummyindex/context/domains/audit/workspace.py:104-140`, `dummyindex/context/domains/config.py:532-551`).
- An audit can scaffold without a pre-existing index. It validates or derives a safe slug, refuses an existing workspace unless forced, and atomically writes `audit.json`, `description.md`, `catalog.json`, plus `findings/` (`dummyindex/context/domains/audit/workspace.py:56-101`, `dummyindex/context/domains/audit/workspace.py:143-213`, `tests/context/domains/audit/test_audit_domain.py:216-281`).
- Persona cards come from the shipped markdown catalog. Roster resolution preserves an installed requested agent, otherwise selects the first capability match, otherwise uses `general-purpose`; when no roster source exists, shipped names remain untouched (`dummyindex/context/domains/audit/catalog.py:56-76`, `dummyindex/context/domains/audit/catalog.py:96-196`).

## Contracts

- `Config` is a frozen schema-v5 record with `scope`, `scope_path`, `mode`, `model`, `auto_refresh_hook`, external-doc and reconcile exclusions, per-command depths, the declarative `wired` ledger, tri-state `default_plugins_enabled`, writer version, doc-guard settings, and the v5 `build` policy object (`BuildPolicy.auto_recouncil`, default true). Subdir scope requires a nonempty path, and default-plugin state accepts only boolean or null (`dummyindex/context/domains/config.py:177-230`).
- `Config.from_dict(payload: dict[str, Any]) -> Config` strictly accepts schema versions 1 through 5, rejects bool-as-version and future versions, validates enums and collection shapes, performs legacy migrations (including `_LEGACY_MODEL_VALUES` model-label mapping), and always returns a current-schema object (`dummyindex/context/domains/config.py:262-354`).
- `default_config(*, platform: str = "claude") -> Config` accepts only `claude`, `codex`, or `both` and returns the corresponding host-aware baseline (`dummyindex/context/domains/config.py:498-529`).
- `read_config(context_dir: Path) -> Config | None` returns `None` only when absent and raises `ConfigError` on malformed or unsupported content; `write_config(context_dir: Path, config: Config) -> Path` stamps the current CLI version and performs a pretty, trailing-newline tmp-and-replace write (`dummyindex/context/domains/config.py:554-568`, `dummyindex/context/domains/config.py:736-756`).
- `migrate_config_in_place(context_dir: Path) -> bool` rewrites only a loadable stale schema or legacy model value and reports whether bytes moved; a legacy model label alone in an otherwise-current config counts as stale (`dummyindex/context/domains/config.py:599-638`).
- `reconcile_default_plugins(context_dir: Path, *, platform: str) -> bool` preserves explicit opt-out, promotes not-applicable state only for Claude-enabled hosts, appends missing defaults after existing entries, avoids no-op writes, and raises on malformed config (`dummyindex/context/domains/config.py:696-733`).
- `resolve_depth(context_dir: Path, command: DepthCommand, depth_flag: str | None) -> CouncilMode` centralizes flag, per-command, global, and standard fallback precedence (`dummyindex/context/domains/config.py:532-551`).
- `onboard.run(args: list[str]) -> int` returns 0 after writing, 2 for invalid arguments or missing `.context/`, and emits the persisted config after its status line (`dummyindex/cli/onboard.py:114-191`).
- `AuditConfig`, `PersonaCard`, and `AuditStart` are frozen, JSON-shaped records. Audit deserialization requires schema 1 and an explicit model; `PersonaCard` retains the originally requested agent when roster resolution rewrites it (`dummyindex/context/domains/audit/models.py:22-126`).
- `resolve_model(context_dir: Path, model_flag: str | None) -> ModelChoice` uses flag then readable config and otherwise raises `ModelRequiredError`; `resolve_mode(context_dir: Path, mode_flag: str | None) -> CouncilMode` delegates to the shared audit depth resolver and translates config errors into audit errors (`dummyindex/context/domains/audit/workspace.py:104-140`).
- `ensure_audit(context_dir: Path, *, description, mode, model, scope=(), slug=None, force=False, personas_dir=None, roster=...) -> AuditStart` creates the deterministic audit workspace and resolved persona menu; it does not select or run the panel (`dummyindex/context/domains/audit/workspace.py:143-213`).
- `load_catalog(personas_dir: Path) -> tuple[PersonaCard, ...]`, `collect_roster(project_root: Path, context_dir: Path) -> tuple[RosterAgent, ...] | None`, and `resolve_catalog(cards, roster) -> tuple[PersonaCard, ...]` form the parse, observe, and pure-resolution pipeline (`dummyindex/context/domains/audit/catalog.py:65-196`).

## Examples

- `dummyindex context onboard --defaults --platform codex` persists `model: "current"`, disables Claude hooks, leaves `wired` empty, and records `default_plugins_enabled: null` (`dummyindex/context/domains/config.py:498-529`, `tests/context/domains/test_config.py:543-573`).
- A v3 canonical Codex baseline with no default-plugin field loads as `null`; the same schema with an explicitly empty non-Codex ledger loads as `false` (`tests/context/domains/test_config.py:1145-1168`).
- Reconciling that Codex baseline for `both` changes the state to `true` and appends all reviewed defaults in one run; reconciling with `platform="codex"` changes no bytes (`tests/context/domains/test_config.py:1203-1251`).
- Starting an audit for `Audit error handling in the CLI dispatcher` derives `audit-error-handling-in-the-cli-dispatcher`, writes the three structured/brief files and findings directory, and round-trips its explicit model and scope (`tests/context/domains/audit/test_audit_domain.py:216-249`).
- A shipped security persona resolves to an equipped security-capability agent while retaining `Security Engineer` as `requested_subagent_type`; a bare repo retains the shipped name because installed global agents are unknowable (`tests/context/domains/audit/test_audit_domain.py:519-589`).
